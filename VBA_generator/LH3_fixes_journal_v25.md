## Ф33. Снята Т-2/Т-1-обёртка расходов целиком (SW_T2 = 0)
- Причина: в конверторе v24 (блок «Т-2/Т-1: FR_C-тройка», Print-строки L2326/L2337) условия веток сгенерированы с дефектом:
  - ветка 1: `(GTc*Fm < 100*e27) and (GTc*Fm > 100*e27)` — противоречие, всегда ЛОЖЬ (ветка «копия расхода от соседа» мертва);
  - ветка 2: `(GTc*Fm < 100*e27) and (GTc*Fm < 100*e27)` — дубль, при малом произведении всегда ИСТИНА → `Fc_r[i,k]:=0` и `Fctr` гасится ×(0.08/1.08) за такт.
- Следствие: замкнутый цикл мёртвого запуска — расход 0 → ветка 2 → расход 0 → навсегда. Расходы в контрольных точках = 0 при любых кранах (подтверждено журналом заказчика: k130hl=1.0 с 13:03:22, k131hl_1=1.0 с 13:04:19 — все F = 0.00 весь прогон, перепады давлений до 10.6 ати).
- «Давление меняется очень быстро» — прямое следствие: нулевые расходы убирают расходное торможение ёмкостей.
- В эталоне 792 (LH1-стадия) обёрток нет — расчёт безусловный, расходы живые.
- Фикс: SW_T2 = 0 в конверторе; в шапке выхлопа LH3_T2 = 0. Тройка возвращается к эталонной форме FR_C + Fc_r + Fctr без corr-коррекции v16 Ф23 (corr уходил только внутри обёртки).
- kerr -971…-975 в выхлопе исчезнут.
- Механика «пара равнозначных расходов» (тупиковые узлы) — возвращать отдельной правкой по восстановленной постановке, условия переписывать заново.

## Ф34. Счётчик Ф0-1 «OI вызовов» — паттерн имени класса
- Причина: oiProc ставился только при ТОЧНОЙ строке `procedure T_Hmodel_UPDT2_0.OI(u1,...,Pfact: Double);`, в Петрофаке класс `T_Hmodel_UKR_0` → флаг не вставал → инкремент LH3_cnt_OI не генерировался → в логе всегда «OI вызовов=0» (при живых 4,97 млн 24К-циклов).
- Фикс: условие заменено на регулярку `^procedure [A-Za-z0-9_]+\.OI\(u1, u2, u3, u4, u5, u6, Tfact, Pfact: Double\);$` (класс из входа). Проверено на обеих строках (UKR_0 и UPDT2_0 — матч; forward-декларация без класса — не матчится, как и задумано).
