# Журнал фиксов LH2 v39 / LH1 v25 — Ф32-пост-резка (25.11.2026)

## Задача
Исключить FPC «Procedure too complex» (E2072, регистровая сложность) на любых процедурах выхлопа Петрофака 19.799 (WorkZero в LH1, Work_12c в LH2) и на будущих входах — не ломая то, что уже работает.

## Причина (установлена FPC-стендом, воспроизведена 1:1)
- E2072 — регистровая сложность, НЕ строковый порог. Work_12c 9557 строк в эталоне 792 компилируется FPC (9/9), в 799 не компилируется: новые стражи LH1/LH2 (freeze-вход + freeze-хвост) обёртывают операторы if-блоками вместо свободных строк — вложенность/регистры выросли при той же длине.
- WorkZero 799 (11562) — монолит: тело без try ~11550 строк, top-level точек реза нет в зоне 15–86% (страж-монолит «if (tup_ind>0) then begin … end;» — 8415 строк без точек). Обычная резка даёт 1651+9895 — не решает. Нужна Ф32а (в-блочная резка с дублированием условия) — механика есть в LH3 v24.
- Work_1..7 (10.2–10.9 тыс., монолиты в 799; в эталоне 792 порезаны CG4, в пайплайне 799 CG4 не прогонялся) — лечатся N-резкой по cand-точкам (итеративно до порога).

## Решение
Единый блок «Ф32-пост-резка (L9)» (одинаковый код в обоих конверторах, L9_-имена не конфликтуют с L1_/L2_):
- LH2_Convert_v39: блок L9 перед Sub LH2_Convert; вызов L9_CutFile после Close #f1, #f2; Dim nCutAll/nPartsAll/nMaxAll; финальный MsgBox-сводка; основная логика v38 не тронута.
- LH1_Convert_v25: то же; детектор повторного прогона расширен «Or InStr(ln, "LH1 v25")» (иначе повторный прогон не ловил v25-маркеры); остальное не тронуто.
- Механика: для каждой процедуры > 5000 строк — (1) Ф32б: тело цикла-переростка > 4000 → части-процедуры, вызовы внутри цикла (подтверждено: Work_12c 8434 → 3 части по ~2816, юнит собрался 0 ошибок); (2) иначе Ф32а: монолит-блок > 4000 → куски с дублированием условия, далее N-резка по стыкам кусков (WorkZero: 4462/2808/4283, юнит собрался 0 ошибок); (3) иначе N-резка по cand-точкам (Work_1..7: по 3 части ~3.4–3.6 тыс.). Локалы var-секций переносятся в поля класса (nm_vn) с переименованием ссылок; декларации частей — после декларации процедуры; Miss_comm-маркеры в конце частей; повторный прогон защищён маркером «Ф32-пост-резка» в файле; при невозможности резки — остаётся как есть.

## Факты стенда (FPC 3.2.2, Петрофак 799)
- до резки: un_hmodel_ukr_1.pas(75913) too complex (12c); un_hmodel_ukr.pas(11744) too complex (WorkZero) — воспроизведено.
- после резки пост-резчиком: un_hmodel_ukr_1.pas — rc=0, 0 ошибок; un_hmodel_ukr.pas — rc=0, 0 ошибок (WorkZero 3 части 4462/2808/4283, Work_1..7 по 3 части).
- эталон 792 (9 юнитов) — 9/9 под FPC и без пост-резки (пост-резчик не трогает процедуры ≤ 5000).

## Ограничения
- Пост-резчик резал в стенде только юниты un_hmodel_ukr (_0i/Work-файл) и un_hmodel_ukr_1; юниты _01 (LOG-процедуры), _2, _3 не проверялись пост-резчиком напрямую (в _2/_3 части ~3.4–5 тыс. и так в пороге).
- «Append»-маркер пишется в конец файла после «end.» — комментарий после end. валиден для FPC.
- При OOM песочницы FPC-компиляция требует повторного запуска (rc=-9 → перезапуск компилятора).
