# Журнал фиксов CG4 v11 (25.11.2026)

База: CG4_Convert_v10.txt (3365 строк) → v11 (3369 строк).

## Ф36. Кавычки в строковых литералах VBA-коде конвертора — только двойные
- Причина: в вставках ФВ1 (реестр виновников NaN) строка-коммент добавлялась как
  `sp.Add '// LH1 v24: реестр виновников - только текущий скан'` — с ОДинарными кавычками.
  В VBA апостроф открывает комментарий до конца строки, поэтому VBA исполняет `sp.Add `
  без аргумента → runtime-ошибка «argument not optional» (подтверждено владельцем в прогоне 25.11).
- Найдено и исправлено 2 вхождения (обе ветки вставки ФВ1):
  - pas-ветка (старая L1913): `sp.Add "// LH1 v24: реестр виновников - только текущий скан"`
  - C#-ветка (старая L1945): та же строка.
- Сама строка-аргумент добавляет в выхлоп комментарий «// LH1 v24: ...» (Delphi/C#) — метка нужна детектору повторного прогона, удалять нельзя.

## Правило (фиксируется по решению владельца 25.11)
В VBA-коде конверторов и журналах все строковые литералы — только в двойных кавычках. Одинарные кавычки в Delphi/C#-выхлопе допустимы только ВНУТРИ двойных (литералы Delphi), например `Log(' ...')`.

## Проверки приёмки
- Проблемная строка: 2 вхождения, оба заменены; одинарно-обрамлённых аргументов `sp.Add '` в файле больше нет.
- Широкая эвристика по файлу (метод/присваивание с апострофом-аргументом вне двойных литералов): только 2 строки — обе VBA-комментарии (шапка v11, исторический коммент v26), не код.
- kerr-маркеры: счётчики 0 расхождений с v10.
- Шапка и MsgBox-итог переведены на v11.
