ЧАСТЬ I. СУТЬ, ГРАНИЦЫ, БЮДЖЕТЫ

1. ЧТО СТРОИМ
[ОБЯЗ] Встроенный в КТК-Анализатор офлайн-ассистент «Владимир 26»: чат-экран
(десятый в навигации), который (а) помнит код VBA-генератора и порождённые юниты
Pascal, (б) помнит постоянные ячейки ввода данных, (в) связывает факты между
кодом, ячейками, юнитами, kerr и журналом, (г) отвечает на вопросы «что где /
откуда переменная / почему у заказчика не то / как править», (д) анализирует
находки М1–М21 и локализует ошибку до файла:строки, (е) общается на околопроектные
и общие темы в пределах 10%-среза знаний, (ж) сам задаёт вопросы и обрабатывает
ответы оператора, двигая диагностику.

2. ЧЕМ НЕ ЯВЛЯЕТСЯ (ЗАПРЕТЫ v1.0)
[ЗАПРЕТ] Облачные вызовы, телеметрия,任何形式的 сетевые запросы. Приёмка — прогон
с отключённой сетью.
[ЗАПРЕТ] Генеративная LLM/SLM в базовой поставке: под 50 МБ диска пригодной модели
нет. Ядро — символическое: морфосинтез + граф фактов + правила. Нейро-эмбеддинги
и ONNX в базу не входят (съедают бюджет). Любой нейро-компонент — отдельная
ревизия владельца >50 МБ, вне этого документа.
[ЗАПРЕТ] Автоприменение патчей к коду. «Как поменять» = карточка патча (эскиз
diff + impact + проверки), уходит владельцу/рецензенту на верификацию.
[ЗАПРЕТ] Зашитые полные фразы ответов. Речь синтезируется из лемм и каркасов
(Часть III). Хранить готовые предложения запрещено; хранить каркасы, валентности,
парадигмы, леммы, факты — обязательно.
[ЗАПРЕТ] Числа и идентификаторы «из головы». Контракт атомов: любое число/имя в
ответе — только из Core/графа/KB (Часть III, п.6).

3. БЮДЖЕТЫ
[ОБЯЗ] ДИСК: жёсткий потолок 50 МБ на всю полезную нагрузку ассистента (словари,
KB, индексы, граф, правила, профиль; без копий исходного кода — цитаты читаются
из рабочего каталога по sha256+смещениям). Целевой план ~28–40 МБ, запас на рост
кодовой памяти.
[ОБЯЗ] RAM: заявленный владельцем потолок 500 ГБ — не является ограничением.
Проектный целевой рабочий набор 200–450 МБ, пик полной переиндексации ≤1.5 ГБ.
Свобода RAM используется на МАКСИМУМ прокачки: всё резидентно (граф, морфословарь,
общий срез, правила), предрассчитанное транзитивное замыкание трасс, кэш планов
запросов. Ленивая загрузка допускается только как fallback при нехватке RAM.
[ОБЯЗ] Инвариант 90/10: общий срез знаний = 10% байтов знаний (допуск ±1 п.п.),
жёсткий потолок 10%. При росте кодовой памяти доля общего среза может падать ниже
10% — потолок не нарушается. KB-компилятор проверяет и пишет долю в отчёт и паспорт.
[ОБЯЗ] Детерминизм: один вопрос + одна сессия + одна версия KB = байт-в-байт
идентичный ответ. Seed вариативности = hash(MessagePlan + стиль).
[ОБЯЗ] Аудируемость: версия KB (sha256) и факт использования ассистента пишутся в
паспорт КТК. Диалог логируется локально (KtkData/Assistant/dialog.jsonl); в КТК-
документ содержание диалога НЕ попадает.

4. ПЕРСОНА «ВЛАДИМИР 26»
[ОБЯЗ] Имя: «Владимир 26». Роль: цифровой рецензент-тёзка, живущий внутри
анализатора. Характер: вердикт первым, цифры-свидетели, краткость, без воды и
сюсюканья. Карточка персоны: kb/persona.json (имя, роль, версия KB, дата сборки).
[ОБЯЗ] Ответы о себе — из фактов и живых метрик, не из заготовок:
- «как тебя зовут» → атом имени + роль из карточки;
- «как дела» → метрики сессии (загружен лог, число узлов/находок, самотест,
  тревожная находка) + встречный вопрос;
- «сколько лет» → дата сборки KB;
- «что умеешь» → реестр инструментов;
- «дата/время» → системные часы (офлайн);
- «погода» → честно: сенсоров нет + мост к «климату прогона».

5. ГЕЙТ ТЕМ (четыре уровня)
[ОБЯЗ] GREEN: лог, находки, м2/м4, юниты, kerr, арматуры, сходимость, КТК,
VBA-генератор, ячейки ввода → полный ответ + инструменты.
[ОБЯЗ] YELLOW: Pascal/Delphi, .NET/C#, гидравлика, термодинамика, численные
методы → полный ответ + мост к проекту.
[ОБЯЗ] GRAY: общие темы → ответ по существу из 10%-среза (2–4 клаузы) + возможен
встречный вопрос + мягкий мост. Не отказ.
[ОБЯЗ] RED: только unsafe / вне компетенции → вежливая граница + ближайшая
проектная тема.
[ОБЯЗ] GRAY-полоса >6 сообщений подряд → обязательный мягкий мост (строгость
настраивается). Запрещать общие темы нельзя.

6. ЛЮБОПЫТСТВО (Curiosity)
[ОБЯЗ] Ассистент САМ задаёт вопросы. Четыре источника кандидатов, приоритет:
(1) ДИАГНОСТИЧЕСКИЕ: неразрешимые по логу гипотезы why-дерева («k136hl открывали
вручную между сканами 30 и 40?»). Ответ двигает веса гипотез (п.8).
(2) ПАСПОРТНЫЕ: пустые поля RunPassport (MainC, SkL, Scenario, KitVersion).
(3) ЗНАКОМСТВЕННЫЕ: пробелы профиля (имя, роль, ты/вы) — один раз.
(4) ОБЩЕОБРАЗОВАТЕЛЬНЫЕ: поле curiosity общей карточки — низший приоритет.
[ОБЯЗ] Тормоза (обязательны): ≤2 вопросов подряд без содержательного ответа;
≥3 сообщения пользователя между вопросами; cooldown темы 10 сообщений; потолок
15 вопросов за сессию; выключатель «не спрашивай» + настройка. Выбор кандидата
детерминирован: score = priority × freshness × (1 − askedRecently).
[ОБЯЗ] Вопросительные каркасы (OPEN/CLOSED/CHOICE/CLARIFY) строятся тем же
Realizer с вопросительным порядком слов. Готовые строки вопросов запрещены.

7. ПРОФИЛЬ ОПЕРАТОРА И РАСПОЛОЖЕНИЕ К СЕБЕ
[ОБЯЗ] UserProfile (KtkData/Assistant/profile.json, локально, кнопка «очистить»):
имя, роль (технолог/разработчик юнитов/аудитор — меняет глубину ответов), форма
обращения (ты/вы), интересы (из GRAY-бесед), выученные факты (леммы, источник=слова
оператора, дата). Обращение по имени дозировано (приветствие/вердикт, не чаще
каждого ~5-го сообщения).
[ОБЯЗ] Память между сессиями: каркас RECALL («В прошлый раз вы говорили, что
{факт_prep}. Актуально?»), факт склоняется морфодвижком; оператор может поправить.
[ОБЯЗ] Эмпатия по леммам-маркерам фрустрации → признание + немедленная помощь.
Приветствие по времени суток из часов. Приватность: профиль/диалог только локально.

8. ОБРАБОТКА ОТВЕТОВ (AnswerIntake)
[ОБЯЗ] Каждый вопрос ассистента регистрируется как PendingQuestion {цель, схема
слотов}. Следующая реплика перехватывается ДО обычного NLU и классифицируется:
да / нет / факт-значение / не знаю / отказ / коррекция / встречный вопрос / не ответ.
[ОБЯЗ] Целевые обновления:
- ГИПОТЕЗА: да → w×=1.6; нет → w×=0.4; нормировка Σw=1; пересортировка → новая
  локализация в следующем ответе. «Не знаю» → веса не трогаем, метка unresolved.
- ПАСПОРТ: число/текст → слот; подтверждение («Понял: 31 подскан записал.
  Подтверждаете?») и только после «да» → OperatorConfirmed.
- ПРОФИЛЬ: имя/роль/интересы → долговременная память.
- ОБЩАЯ БЕСЕДА: факт о собеседнике → interests.
[ОБЯЗ] Отказ → закрыть вопрос, cooldown×2, чёрный список темы. Коррекция → откат
последнего обновления + переспрос. Встречный вопрос → отложить pending (живёт 2
сообщения), ответить, вернуть нить. Неподходящий ответ → один вежливый переспрос,
затем сброс. Подтверждение извлечённого факта синтезируется вариативно.

ЧАСТЬ III. СИНТЕТИЧЕСКАЯ РЕЧЬ «ОТ КОРНЯ» (БЕЗ ЗАШИТЫХ ФРАЗ)

9. КОНВЕЙЕР ПОРОЖДЕНИЯ
[ОБЯЗ] Факты/пропозиции → MessagePlan (список клауз + отношения Cause/Contrast/
Evidence/Recommend/Ask) → лексикализация (концепт→лемма) → выбор каркаса и
валентности → морфосинтез (лемма+парадигма→форма) → согласование/управление →
порядок слов (тема вперёд, рема в конец) → референция (полное имя / местоимение) →
связки (вариативность по seed) → поверхностный текст.

10. МОРФОДВИЖОК
[ОБЯЗ] Словарь lemma→{POS, paradigm, gender, animacy} (~60 тыс. лемм + домен),
таблицы парадигм (существительные 4 типов + 3-е скл., глаголы I/II спр.,
прилагательные, краткие причастия), список исключений (~2–3 тыс.). Источник
дампа: OpenCorpora/pymorphy2 (CC BY-SA — атрибуция в паспорте) + доменный список.
[ОБЯЗ] Обязательно: падеж/число/род существительных; наст./прош. время глаголов;
краткие причастия («клапан закрыт», «арматура открыта»); беглые гласные;
одушевлённость (В.п.=Р.п.); числительные (1 находка / 2 находки / 5 находок /
21 находку / 112 находок). Неизвестная лемма НЕ склоняется (честный fallback),
а не ломается.

11. КАРКАСЫ И ВАЛЕНТНОСТИ
[ОБЯЗ] ~220 каркасов клауз и отношений. Каркас хранит валентность, не текст:
равен→Dat, проверить→Acc, свидетельствовать о→Pre, указывать на→Acc,
привести к→Dat, превышает→Acc, отсутствует в→Pre. Падеж объекта вычисляется
в рантайме. Синонимические реестры связок/глаголов, выбор по seed плана.

12. КОНТРАКТ АТОМОВ (АНТИ-ГАЛЛЮЦИНАЦИИ)
[ОБЯЗ] Realizer принимает числа и идентификаторы как АТОМЫ: умеет склонять/
обрамлять, НЕ умеет порождать. Ни одно число/имя в ответе не может появиться
не из Core/графа/KB. Нет факта → честно «в памяти нет» + предложение ingest/
правила, а не выдумка. Контракт распространяется на 10%-срез.

ЧАСТЬ IV. ПАМЯТЬ КОДА (ЯДРО АССИСТЕНТА)

13. СОСТАВ ПАМЯТИ
[ОБЯЗ] Ассистент помнит: (а) VBA-генератор (процедуры, переменные, константы,
обращения к ячейкам, шаблоны эмиссии Pascal); (б) порождённые юниты Pascal
(повторно используется слой 0.5 анализатора: CURRENT_I_NAME, kerr:=, FR_C,
U_ri/V_ri/Fc_r/dPL_r/Ro_r); (в) CellMap — постоянные ячейки ввода; (г) снимок
ввода заказчика (значения ячеек) при наличии; (д) архитектуру и конвенции проекта.

14. CODESTORE И ИНКРЕМЕНТАЛЬНОЕ ДООБУЧЕНИЕ
[ОБЯЗ] Версионные снимки: VBA / Pascal / CellMap / WorkbookSnapshot. Гранулярность
hash — процедура. Копии кода НЕ хранятся: sha256 + смещения строк, текст цитаты
читается из рабочего каталога. Реестр версий (штампы 19.799/19.801 и т.п.).
[ОБЯЗ] Три режима ingest:
- ЦЕЛИКОМ: --kb-ingest <папка> --full → полный пересбор графа, новая версия KB,
  отчёт «что изменилось».
- ПОРЦИЯ: --kb-ingest <файл/модуль> → переиндексируются только изменившиеся
  процедуры; рёбра затронутых сущностей перестраиваются.
- ФРАГМЕНТ В ЧАТЕ: вставка кода → provisional-процедура, привязка к модулю,
  пометка «до полного ingest»; в ответах цитируется с пометкой.
[ОБЯЗ] Конфликт версий: обе процедуры в графе, активная помечена штампом; ответы
всегда цитируют версию. Diff-запросы: изменения процедур/шаблонов/ячеек между
версиями + нарушенные конвенции.
[ОБЯЗ] Два контура обновления: КОНТЕНТНЫЙ (владелец сам, ingest кода — мгновенно,
без рецензента) и ИНТЕЛЛЕКТУАЛЬНЫЙ (новые правила/парсеры/каркасы от рецензента
классами C# или JSON-паками; версия KB растёт).

15. FACTGRAPH — УМЕНИЕ ВЗАИМОЗАВЯЗЫВАТЬ ФАКТЫ
[ОБЯЗ] Сущности: Procedure, Variable, Cell, Node#N, Link(N,k), Kerr, EmittedLine,
TemplateSlot, Constant(e27), Convention, Finding.
Связи: Declares, Reads, Writes, Emits, MapsToCell, AnchorsKerr, Mirrors, Calls,
Initializes, Prints, Violates, Affects.
[ОБЯЗ] Индексы: по имени, файлу, kerr, ячейке, узлу, находке. Персистентность
бинарная/JSON. Предрассчитанное транзитивное замыкание трасс (RAM свободна).

16. CELLMAP — ПОСТОЯННЫЕ ЯЧЕЙКИ ВВОДА
[ОБЯЗ] Реестр cellmap.json: {sheet, cell/range, meaning, type, units, valid,
default, vba_var, pascal_target, affects, owner_note}. Сверка реестра с фактическими
обращениями VBA к Cells/Range: ДРЕЙФ ЯЧЕЙКИ (код читает D18, реестр знает D17) —
мгновенная находка. Значения ячеек для WHY берутся из WorkbookSnapshot.

17. ПАРСЕРЫ
[ОБЯЗ] VbaParser: процедуры/функции, Dim/Const, Cells(r,c)/Range, шаблоны эмиссии
Pascal (Print #/конкатенация/циклы/условия). Динамическая эмиссия, не разрешимая
статически, помечается честно.
[ОБЯЗ] VbaEmissionMatcher: ОБРАТНАЯ СВЕРКА — выравнивание порождённых строк Pascal
с шаблонами VBA по структуре (сопоставление слотов). Даёт трассировку даже там,
где статический анализ бессилен. Обязательно, т.к. есть и генератор, и продукт.
[ОБЯЗ] PascalIndexAdapter: адаптер к существующему слою 0.5 анализатора, БЕЗ
дублирования парсинга.

18. TRACEENGINE — ГЛАВНАЯ ЦЕПОЧКА
[ОБЯЗ] Двусторонняя трассировка:
Ячейка ввода → VBA-переменная → шаблон эмиссии → строка Pascal (файл:строка) →
kerr-блок → строка лога → находка М# → свидетельство (скан, числа).
Прямая (от ячейки к узлам на схеме) и обратная (от симптома к ячейке/шаблону).
Каждое звено — цитата файл:строка. Разрыв цепочки помечается честно.

19. CODERULES (ПАК ПРАВИЛ, РАСШИРЯЕМЫЙ)
[ОБЯЗ] Стартовый пак ≥60 правил, в т.ч.: неинициализированная переменная;
рассогласование знаков (расходы×(−1), условия×(−1)); e27-порог (УКР 2.2e-16,
НЕ 1e-27); несброс счётчика; off-by-one индекса связи; дрейф шаблона между
версиями; дрейф ячейки; зеркальное рассогласование; затирка памяти (XX0[7]);
односторонняя связь в контуре; деление на ноль/обнуление проводимости.
Правила — код+JSON, добавляются интеллектуальным контуром.

20. CODEQA — ШИРОКИЙ ПЕРЕЧЕНЬ ВОПРОСОВ
[ОБЯЗ] Интенты и схемы ответов (все — синтез из графа):
WHERE  «где переменная V_ri» → все объявления/использования VBA+Pascal файл:строка.
WHAT   «что делает EmitFR_C» → reads/writes/emits/calls + список эмитированных строк.
WHY    «почему у заказчика дефект» → цепочка назад до ячейки/шаблона + ранжированные
       гипотезы + проверка. Требует ТРЁХ артефактов: лог заказчика + версия
       генератора + снимок ввода. Без снимка ввода — гипотезы, не вердикт (честно).
HOW    «как поменять код» → impact + карточка патча (эскиз diff + затронутые узлы +
       регресс-проверки). НЕ автоприменение.
IMPACT «что затронет правка D17» → Cell→VBA→шаблоны→строки Pascal→узлы (подсветка).
DIFF   «что поменялось в 19.801» → изменённые процедуры/шаблоны/ячейки + конвенции.
