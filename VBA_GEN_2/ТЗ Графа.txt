ЧАСТЬ I. СУТЬ И ИНТЕГРАЦИЯ
================================================================================

--------------------------------------------------------------------------------
1. ЧТО СТРОИМ
--------------------------------------------------------------------------------
[ОБЯЗ] Блок «Схема»: автоматическое построение ИНТЕРАКТИВНОГО ГРАФА гидравлической
схемы м2 по сборке юнитов м2 (исходники-юниты) с пополнением/сверкой данными из
отладочного журнала. Граф отображается на 2D-конве внутри текущего приложения
КТК-Анализатор и сохраняется в файлы (картинка + модель + позиции).
[ОБЯЗ] На линиях графа между узлами рисуются ЗНАЧКИ АРМАТУР — ровно так, как заложено
в топологии юнитов: для каждой связи с арматурой — значок в состоянии последнего
скана (закрыт/открыт/дроссель % откр.). Разбор топологии арматур обязателен и
проверяется 1:1 с журналом.
[ОБЯЗ] Аппараты (насосы, колонны, ёмкости, теплообменники, печи, сепараторы) обозначаются
на графе ИНАЧЕ, чем трубные узлы: у каждого типа — своё узнаваемое обозначение
(иконка/форма), перечень в разделе 25.
[ОБЯЗ] Конва интерактивна: наведение — подсказка, клик — карточка объекта с данными
последнего скана, перетаскивание узлов, зум/панорама, фильтры, проигрывание сканов.

--------------------------------------------------------------------------------
2. ИНТЕГРАЦИЯ В ТЕКУЩЕЕ ПРИЛОЖЕНИЕ
--------------------------------------------------------------------------------
[ОБЯЗ] Интеграция — без вилки продукта и без forks проекта: тот же репозиторий/сборка,
тот же .NET 8/WinForms, тот же KtkData. Правила:
1) Новый экран «Схема» (девятый в навигации, после «Сравнение») и/или замена текущего
   экрана «Топология» — владельцем принимается вариант: ТЗ закладывает замену «Топологии»
   с сохранением всех её функций (клик-панели, красные пунктиры соседей без карточек).
2) Модель графа строится из МОДЕЛИ ЛОГА (слоя 1 ТЗ-анализатора) + ПАРСИНГА ЮНИТОВ
   (новый слой 0.5: «Парсер юнитов», см. Часть III). Парсер юнитов НЕ меняет ядро
   анализатора и НЕ ломает приёмку v1.2 (весь существующий самотест обязан остаться
   зелёным).
3) Данные для отрисовки состояния (степени арматур, давления, расходы) — из модели
   последнего скана журнала; при отсутствии журнала — только топология из юнитов
   (режим «без сканов»: значки в нейтральном состоянии, цифры не показываются).
4) Индекс kerr→код (раздел 43 ТЗ-анализатора) используется парсером юнитов как
   карта блоков: узловые блоки 118xxx/157xxx/178xxx/2000xx/247xxx и карточки −200..−208.
5) Обучение (Часть V ТЗ-анализатора) распространяется и на парсер юнитов: нераспознанные
   строки юнитов попадают в очередь «Не понял — дообучи?» (раздел 7.4 руководства).
6) Экраны «Находки» и «Диагностика» получают функцию «показать на схеме» — подсветка
   объекта/связи на графе (взаимная навигация).

--------------------------------------------------------------------------------
3. ИСТОЧНИКИ ДАННЫХ И ПРИОРИТЕТЫ
--------------------------------------------------------------------------------
[ОБЯЗ] Два источника, иерархия:
- СБОРКА ЮНИТОВ м2 (исходники: эталон 19.785 и т.п., CP1251) — ПЕРВИЧНЫЙ источник
  топологии: типы узлов и аппаратов, перечень связей, геометрия (D, L), io-коды
  штуцеров, перечень арматур на связях и их имена, состав аппаратов (секции колонн,
  контуры печей/Т/О), ёмкости и объёмы.
- ЖУРНАЛ (модель слоя 1) — подтверждение и динамика: соседи из «связи_1:», геометрия
  из «связи_2:», арматуры из «k_ ARM:» и строк «арм.», карточки аппаратов (pmp_/fur_/
  col_/exc_), состояния на каждый скан.
[ОБЯЗ] Правило согласования: топология юнитов и топология лога ДОЛЖНЫ совпасть;
расхождения — находки (класс «схема↔журнал»): сосед есть в юните, но нет в логе
(как существующие «соседи без карточек»), арматура есть в юните, но не печатается
(баг печати k136hl-эры — узнаваемо), имена узлов не совпали (суффиксы _1, переименования).
[ОБЯЗ] Штамп версии юнитов («// ОТЛАДКА ... -VP19.785» / «26. 11 ( 8: 54) -VP19.801»)
проверяется на соответствие паспорту прогона; несовпадение версии юнитов и версии
комплекта в паспорте — предупреждение (раздел 40 ТЗ-анализатора).

--------------------------------------------------------------------------------
4. УЗЛЫ ГРАФА
--------------------------------------------------------------------------------
[ОБЯЗ] Узел графа = расчётный узел м2: {номер (#N), имя (t_201_s03), физический тип,
аппаратный тип (см. 5), свойства из карточки: P, Tc, V, H, H_0, GTc, Fm, G_in/G_out,
STORE, Em, L_, составы (осн:/UL/UG), MODEL (UPDT1/UPDT2/UKR...), METH-№}.
[ОБЯЗ] Классификация узла по типу (определяется по таблице признаков раздела 17):
- ТРУБНЫЙ (TUBE) — тип- 0 в карточке «ист. #»;
- АППАРАТ (OI) — тип- 1 в карточке «ист. #» + карточка аппарата (pmp_/fur_/col_/exc_);
- КРАЙНЯЯ ТОЧКА (БУИ) — печатается «==> БУИ.» и/или числится в сводке «Б У И: n=86»
  — крайняя точка, давление/состав заданы заказчиком/пресетом;
- ТУПИК — узел с F=0, G_in=G_out=0 (метод М2 уже находит);
- СЕКЦИЯ КОЛОННЫ — секционные узлы col_ (вертикальная цепочка секций одной колонны).

--------------------------------------------------------------------------------
5. АППАРАТНЫЕ ТИПЫ (обозначаются иначе — см. раздел 25)
--------------------------------------------------------------------------------
[ОБЯЗ] Аппаратный тип узла:
- НАСОС/КОМПРЕССОР (pmp_) — направленный элемент с 4 клеммами PI/PIP/POP/PO;
- ПЕЧЬ (fur_) — с контурами (КОНТУР N, F(среды), KF конв./рад.);
- КОЛОННА (col_) — с секциями (секция N: GTc/Fm/Tc/P/L_/Fc_верх/Fc_низ/H/H0/V);
- ТЕПЛООБМЕННИК (exc_) — пара (−имя1:имя2−) с двумя контурами и REG;
- АППАРАТНЫЙ КОНТУР Т/О (ac_/ack_) — контур с воздухом/средой (V1);
- ЁМКОСТЬ/СЕПАРАТОР (OI с уровнем) — тип- 1, V/H/H_0, STORE, Em/L_;
- АРМАТУРА КАК УЗЕЛ — арматура, у которой печатается собственная карточка «арм.»
  (большинство арматур — элементы рёбер, см. 6; у крупных арматур есть карточка).

--------------------------------------------------------------------------------
6. РЁБРА ГРАФА И АРМАТУРЫ НА НИХ
--------------------------------------------------------------------------------
[ОБЯЗ] Ребро = связь между узлами: {узлы A/B, массивная позиция пары (из «связи_1:»
и U_ri), геометрия (D, L из «связи_2:»), io-коды концов (S/S, S/L, S/G), список
арматур на ребре (упорядочен как в «k_ ARM:»), направление/ток последнего скана
(V_ri, Fc_r), находки по связи}.
[ОБЯЗ] Арматура на ребре — три вида признаков:
1) Клапан-дроссель: имя вида k419/k412/k136hl/k130hl/kt_101_s02_oi — степень открытия
   0.0..1.0 (0.0 закрыт, 1.0 полностью открыт, промежуточные — дроссель);
2) Клеммная арматура: имя с префиксом ok_ (_ok_ipog_voda1=1.0) — открытая/закрытая
   клемма узла;
3) Насосная клемма: pi_/pip_/po_/pop_ на насосе (см. 13).
[ОБЯЗ] Каждый значок арматуры на ребре обязан иметь: имя, текущую степень открытия,
ссылку на источник данных («k_ ARM:» узла A / «арм.»-строка / переменная юнита),
и ТОЧНО соответствовать перечню арматур топологии (1:1 с «k_ ARM:» и «арм.»-строками).
Дубли/пропуски — находка класса «схема↔журнал».

--------------------------------------------------------------------------------
7. ЗНАКИ И КОНВЕНЦИИ (критично для отрисовки стрелок/толщин)
--------------------------------------------------------------------------------
[ОБЯЗ] Знак расхода на ребре:
- печатное значение в «расходы:» = Fc_r·(e27−1) ≈ −Fc_r — ЗНАК ПЕРЕВЁРНУТ
  относительно массивной величины (конвенция ТЗ-анализатора 8.7);
- в «арм.»-строке F=Fc_r — БЕЗ переворота;
- анализатор обязан использовать ЕДИНУЮ нормированную величину: F_ребро = Fc_r
  (не печатную), знак притока на узле = V_ri·(−1) по «условия:»;
- ПЕРЕД приёмкой направления обязаны быть сверены на эталоне 19.785 (не менее 5
  проверенных связей с заведомым направлением, подтверждённым владельцем).
[ОБЯЗ] Магия e27: e27 = 1e-27 (в УКР-сборках 2.2e-16); множители с e27 служат
заменителями нуля — НЕ путать «нулевой расход» с «расходом, напечатанным с e27-множителем»
(например Fc_pip = e27 − Fc_r[116,1] в колонне — знак и смысл как у Fc_r, см. 15).

ЧАСТЬ III. ПАРСИНГ СБОРКИ ЮНИТОВ м2 — ПО КАЖДОМУ ТИПУ ОБЪЕКТА
================================================================================
[ОБЯЗ] Общие правила парсинга юнитов:
1) Кодировка CP1251 (в выхлопах м4 — UTF-8); юниты определяются по unit-строке
   (unit un_hmodel_ukr…) и штампу версии во 2-й строке;
2) Привязка к узлам — по якорям: «CURRENT_I_NAME:='№N-имя'; kerr:= <диапазон>;»
   (N — номер узла, диапазон kerr = блок, см. раздел 27 ТЗ-анализатора);
3) Связи узла — по массивным позициям: U_ri[N,1..K] — проводимости связей узла N
   (K = число связей узла); dPL_r[N,k] — перепады; Ro_r[N,k] — плотности;
4) Соседи по именам: сосед узла N на позиции k — переменная давления соседа в
   сравнении (tr2_t_201_1 — имя соседа узла 100 на позиции 1);
5) Комментарии-заголовки: «// Д А В Л Е Н И Я», «// РАСХОДЫ И СВОЙСТВА», «// ТУПИКИ»,
   «// СМЖР», «//...ПЕЧАТНЫЕ РАСХОДЫ..........._» — разметка блоков С1–С8;
6) Всё, что не распознано, — в очередь «Не понял — дообучи?» (с примером и кнопками).

// # 100 Давление и расход для t_201_s03 (часть 2 - РАСХОДЫ)

- V_ri[100,k] — знак направления; dPL_r — перепад; KG/KL/KW_r — фазные проводимости.
- Тип узла — по карточке журнала «ист. # 100 ... тип- 1» (тип- 1 = OI/аппарат,

9. АРМАТУРЫ: РАЗБОР ТОПОЛОГИИ АРМАТУР (ОБЯЗАТЕЛЬНЫЙ БЛОК ТЗ)
--------------------------------------------------------------------------------
[ОБЯЗ] Арматуры собираются из ТРЁХ источников (сверка между собой обязательна):
9.1. ИЗ КАРТОЧКИ УЗЛА в журнале «k_  ARM:»:
```
k_  ARM:  +A1( 92)()++A2( 8)(_ok_ipog_voda1=1.0)+ 
```
Формат: +A<k>( <связь>)(<пар-ры>)+ — A<k> — арматура №k узла, <связь> — массивная
позиция связи, в скобках — клапаны с проводимостями: (_ok_ipog_voda1=1.0) — клеммная
арматура открытая; (_k419=0.0) — клапан закрыт.
9.2. ИЗ ОТДЕЛЬНОЙ АРМУРНОЙ СТРОКИ журнала (WorkLog10/11, 879 строк/184 шаблона):
```
арм. k136hl=0.00  tr170( 151)=0.25 ати (18.54*C);  frak_nk_85_umt_1( 212)=12.10 ати (49.67*C); F=0.00 т/ч.
```
Формат: имя_арматуры=<степень> <сосед1>(<св1>)=<P1> ати (<T1>*C); <сосед2>(<св2>)=<P2>
ати (<T2>*C); F=<расход> т/ч. — паре соседей сопоставляются массивные позиции связей
(в скобках), расход F=Fc_r[212,1] — РАСХОД РЕБРА «связь 1 узла 212».
[ОБЯЗ] Известный дефект печати: в эре k136hl F печатается 0.00 во всех арм.-строках
при реальном потоке (Ф33-семейство) — анализатор обязан отличать «баг печати» от
«реального нуля» (по расходованию зеркальной связи из карточек узлов).
9.3. ИЗ СБОРКИ ЮНИТОВ: переменные-степени (_k419, k136hl, kt_101_s02_oi), клеммные
(ok_<имя>), их значения в присваиваниях; ИХ СВЯЗЬ С УЗЛАМИ — по появлению в узловых
блоках (сосед рядом с именем арматуры) и по Fc_r[узел, позиция] в арм.-литерале.
[ОБЯЗ] Результат: РЕЕСТР АРМАТУР: {имя, тип (клапан/клемма/насосная клемма), узел A,
узел B, массивная позиция, степень (ряд по сканам), источник}. Каждый значок на графе
ссылается на этот реестр. Проверка полноты: перечни из трёх источников сходятся;
расхождения — находки.

[ОБЯЗ] Правила парсинга насоса:
1) Идентификация в юните: семейство переменных pi_<имя> / pip_<имя> / po_<имя> /

3) Em(pi) — испаряемость на входе (критерий кавитации);
4) Fc(pi_pip)/Fc(pop_po) — расходы входного и выходного звеньев (т/ч);
5) В графе: насос — НАПРАВЛЕННЫЙ элемент (вход→выход), стрелка обязательна;
   на графе клеммы — 4 точки, но для простоты рёбра сходятся в 2 узла (вход-узел,
   выход-узел), клеммы PIP/POP показываются на иконке насоса;
6) Насосные блоки в юнитах — kerr 2000xx (узловая математика насоса в _2);

18. ТРЕБОВАНИЯ ВЛАДЕЛЬЦА К РАСКЛАДКЕ (обязательные критерии качества)
--------------------------------------------------------------------------------
[ОБЯЗ] Раскладка графа обязана удовлетворять:
1) МИНИМАЛЬНАЯ СУММАРНАЯ ДЛИНА ЛИНИЙ: сумма длин рёбер минимальна при прочих равных
   (критерий оптимизации);
2) ОПТИМАЛЬНАЯ РАЗНЕСЁННОСТЬ УЗЛОВ: узлы не слипаются и не разлетаются; равномерное
   отталкивание; минимальные зазоры (пиксельная норма, настраивается);
3) КРАЙНИЕ ТОЧКИ ПО КРАЯМ ПОЛЯ: БУИ/источники/стоки (граничные узлы) прижимаются
   к краям поля построения (по стороне — по компасу от центра), аппараты — ближе
   к центру поля;
4) РЁБРА НЕ ПЕРЕКРЫВАЮТ УЗЛЫ И ЗНАЧКИ АРМАТУР; подписи читаемы;
5) ДЕТЕРМИНИРОВАННОСТЬ: при одинаковом входе (юниты+журнал) раскладка одинакова
   (фиксированный seed); повторный прогон не «пляшет»;
6) КАЧЕСТВО НА РЕАЛЬНЫХ СХЕМАХ: 483 узла, ~700 рёбер, цепочки/кольца/ветвления
   (тесты — эталон 19.785 и журналы УПДТ-2/УКР).

19. АЛГОРИТМ РАСКЛАДКИ (трёхфазный)
--------------------------------------------------------------------------------
[ОБЯЗ] Фаза 1 — СЛОЕВАЯ (Sugiyama-подобная) ИНИЦИАЛИЗАЦИЯ: направленный граф от
крайних точек (БУИ/источники/стоки) — слои по расстоянию от границы; слои — вертикальные
(или по главному направлению потока); крайние точки — на крайних слоях (края поля);
внутрислоевой порядок — по числу связей с соседними слоями (barycenter).
[ОБЯЗ] Фаза 2 — СИЛОВАЯ ДОВОДКА (force-directed):
- пружинные силы на рёбрах: длина покоя ребра зависит от D/L и числа параллельных
  связей (шире труба — длиннее ребро по умолчанию, параллельные связи — плотнее);
- отталкивание узлов (по теореме Кулона/слабое — по массе: аппараты тяжелее);
- сила-границы: узлы не выходят за поле; крайние точки — притягиваются к краям
  (пружины к границам по их стороне);
- агрегаты (секции колонны, контуры Т/О) — ЖЁСТКИЕ пружины (не растягивать);
[ОБЯЗ] Фаза 3 — ПРИЧЁСЫВАНИЕ: выравнивание на неявную сетку (магниты), устранение
пересечений рёбер с узлами (локальный сдвиг/изгибы), ортогонализация маршрутов рёбер
(точки перегиба), распределение значков арматур по маршруту ребра.
[РЕК] Итерации с визуальным прогрессом; возможность «отменить и пересчитать».

[ОБЯЗ] Контекст: схема м2 — не только граф, но набор замкнутых контуров (насос → печь →

34. СВЕДЕНИЕ КОНТУРНЫХ БАЛАНСОВ (Loop Balancing) — [ОБЯЗ]
--------------------------------------------------------------------------------
1) Поиск циклов: базовые циклы графа (по остову) — полный перечень замкнутых контуров
   (в т.ч. через аппараты: насос→печь→колонна→Т/О); контуры через КРАЙНИЕ ТОЧКИ (БУИ)
   не замыкаются (БУИ — граница модели): для них — только структура, без невязок;
2) для каждого контура и каждого скана:
   - невязка расхода: ΣF_in − ΣF_out по сечениям контура (на нормированных Fc_r,
     конвенция раздела 7);
   - невязка давления: (P_начало − P_конец по замкнутому обходу) − Σ ΔP_рёбер
     (по dPL_r/«условия:»);
3) смысл: локально связь может сходиться (М1), а по контуру накапливается «фантомный»
   расход — признак системной ошибки матрицы проводимостей U_ri, которую М1 не видит;
4) контуры с накопленной невязкой — находка (серьёзность по порогу) + подсветка на
   графе КОНТУРОВЫМ ОРЕОЛОМ (красная обводка вдоль замкнутого пути);
5) список контуров с невязками — отдельная вкладка экрана «Схема»; сортировка по
   величине невязки; клик — подсветка контура и его рёбер.

--------------------------------------------------------------------------------
35. МЁРТВЫЕ ЗОНЫ И ОБВОДНЫЕ ЛИНИИ (Bypass & Dead-ends) — [ОБЯЗ]
--------------------------------------------------------------------------------
1) Топологические мёртвые зоны: подграфы, отсечённые от остальной схемы арматурами со
   степенью 0.0 на ВСЕХ входах, но содержащие объём (V>0 и/или STORE G/L/W>0) — зоны
   риска скопления тяжёлых фракций/застоя тепла;
2) визуализация: отсечённый подграф — серым с пунктирной границей («Isolated Island»);
   подсказка: перечень перекрывающих арматур; при открытии арматуры по сканам — зона
   «оживает» (анимация показывает границу);
3) обводные линии (bypass): параллельные пути между одной парой узлов — выделяются
   и подсчитываются; изменение распределения потоков по параллельным путям между
   сканами — данные для сравнения прогонов;
4) отчёт по мёртвым зонам в КТК: объём, время изоляции (по сканам), перекрывающие
   арматуры.

--------------------------------------------------------------------------------
36. ДЕТЕКТОР СТАЦИОНАРА (Steady-State Detector) — [ОБЯЗ]
--------------------------------------------------------------------------------
1) ряд глобальной невязки Σ|P_i(t) − P_i(t−1)| (и Σ|ΔP_рёбер|) по сканам;
2) автоматическое определение «зоны стационара»: максимум ряда ниже порога ε_ст
   (настраивается, согласован с τ затухания слоя 1.5 ТЗ-анализатора);
3) кнопка «Зафиксировать стационар»: сохраняет текущий скан как ЭТАЛОННЫЙ СНИМОК
   графа (позиции + состояния арматур + уровни + расходы) для сравнения/приёмки;
   снимки версионируются (в reference_run.json).

--------------------------------------------------------------------------------
37. ИНДИКАТОР РИСКА ГИДРАВЛИЧЕСКОГО УДАРА — [ТВОРЧ, НЕ В ПЕРВОЙ ПОСТАВКЕ]
--------------------------------------------------------------------------------
1) идея: по ряду степени K(t) арматуры вычислять dK/dt; если клапан закрывается
   быстрее, чем фронт давления проходит ребро (τ = L/c, c — скорость звука в среде),
   — предупреждение «риск гидроудара» на ребре;
2) ЖЁСТКИЕ ОГОВОРКИ (иначе — не делать):
   - скорость звука в юнитах НЕ задана: допущение (жёсткая труба, c = 1000–1400 м/с
     по среде из Ro_r/Tc) ОБЯЗАНО подписываться в находке как ОЦЕНОЧНОЕ;
   - это индикатор риска по кинематике печати, а НЕ гидродинамический расчёт —
     серьёзность только «ИНФО/ВНИМАНИЕ (оценка)», не «ОШИБКА»;
   - не блокирует остальные методы и приёмку.

41. ACTION RECOMMENDER — [ТВОРЧ, НЕ В ПЕРВОЙ ПОСТАВКЕ]

1) идея: от гипотезы дерева диагнозов — к рёбрам-кандидатам воздействия: «чтобы

42. PVT-ОКНО (ФАЗОВАЯ ДИАГРАММА УЗЛА) — [ТВОРЧ; СВЯЗАНО С ЗАМОРОЖЕННЫМИ ПРОЕКТАМИ]
--------------------------------------------------------------------------------
1) идея: для выбранного узла — окно PVT: фазовая диаграмма (P-T envelope) по составу
   фаз (UL/UG) и отметка текущей рабочей точки (P, Tc) — оператор видит зону
   двухфазного потока/ретроградной конденсации без выгрузки данных;
2) ОГОВОРКА: BUDcad/TecHet — в статусе [ЗАМОРОЖЕН]; интеграция с их модулями — только
   по явной команде владельца; без них окно строится по встроенным корреляциям
   (Генри + гибрид водной фазы, решение В.8) — отдельная задача, НЕ в поставку 1.

44. ЭКСПОРТ В DXF/XML (P&ID) — [РЕК] DXF, [ТВОРЧ] XML CAESAR/HYSYS

1) DXF (формат R12, текстовый, без библиотек) со слоями: Трубы / Арматура / Аппараты /

2) DWG — закрытый бинарный формат: НЕ РЕАЛИЗОВЫВАТЬ; путь — DXF;
3) XML для CAESAR II / HYSYS — только по предоставленным образцам схем XML этих
   продуктов; без образцов формат НЕ ВЫДУМЫВАТЬ.

45. КЛАСТЕРИЗАЦИЯ (СУПЕР-УЗЛЫ / ГРУППИРОВКА) — [ОБЯЗ]
--------------------------------------------------------------------------------

   рёбра; карточка супер-узла — агрегат (число узлов, суммарный вход/выход, перечень
   внутренних объектов, находки внутри);
2) обратная развёртка в один клик; группы сохраняются в positions.json (версия+sha256);
3) автоматические предложения групп: секции колонн (уже есть), компоненты связности,
   мёртвые зоны (раздел 35), кусты вокруг аппаратов.
