РАЗДЕЛ 2. ДОПОЛНИТЕЛЬНЫЕ ЗАМЕЧАНИЯ ПО КОДУ (найдено независимо, проверено в сборнике)

--------------------------------------------------------------------------------
2.1. Контурная невязка: односторонние рёбра пропускаются МОЛЧА (важно).
--------------------------------------------------------------------------------
GraphAnalytics.ComputeLoopBalances: ребро участвует в сумме только если FlowAtA И
FlowAtB не-NaN; односторонние рёбра (расход напечатан с одной стороны) выбрасываются
из невязки без следа. Математика: невязка контура = Σ зеркальных невязок рёбер цикла
+ вклад односторонних рёбер. Для полностью зеркального контура «фантомный расход,
которого М1 не видит» НЕ существует — М1 видит каждую пару. Главная самостоятельная
ценность контура — именно односторонние связи (М1 по ним вообще не работает).
РЕШЕНИЕ (совпадает с п. 7 чек-листа СС, подтверждено кодом):
  - LoopDefect разделить: MirrorSum (сумма зеркальных невязок) + OneWaySum (сумма
    модулей односторонних значений по циклу) + Counter (число односторонних рёбер);
  - в находке LOOP печатать все три составляющие;
  - контуры, где все рёбра односторонние — сейчас получают NaN (не считаются вовсе);
    для них OneWaySum = сумма модулей — это и есть их «невязка».
Дополнительно: невязка считается ТОЛЬКО по последнему скану, а ТЗ «Граф» (раздел
34.2) требует по каждому скану — пересчитывать в проигрывании сканов.

--------------------------------------------------------------------------------
2.2. Стрелка ребра строится только по стороне A.
--------------------------------------------------------------------------------
GraphModel: e.Flow = last.FcAtA. Если сторона A не напечатала расход (односторонняя
связь), а сторона B напечатала — Flow остаётся NaN, ребро без стрелки и толщины.
РЕШЕНИЕ: FlowAtA = FcAtA, если есть; иначе −FcAtB (конвенция «+ приток к A»:
приток к B = отток к A, знак переносится инверсией). Стрелка на схеме — по
фактическому направлению последнего скана в любом случае.

--------------------------------------------------------------------------------
2.3. Фолбэк KOI8-R — фактически мёртвая ветка.
--------------------------------------------------------------------------------
Normalizer.DetectEncoding: CP1251 декодирует ЛЮБЫЕ байты без ошибок, поэтому
TextLooksValid почти всегда пройдёт на CP1251 и KOI8-R никогда не будет выбран.
Если журнал реально в KOI8-R — прочитается как CP1251 с валидными буквами (mojibake).
Практически KOI8-журналов м2 нет — не блокер.
РЕШЕНИЕ (лёгкое): после нормализации считать долю распознанных строк шаблонами;
если строк много, а карточек 0 — жесткое EncodingWarning «формат не опознан».

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
Поле FcAtA/FcAtB комментировано как «„расходы:" печатные (знак: + приток к
владельцу)» — после фикса ZM-Баг №1 значения хранятся НОРМАЛИЗОВАННЫМИ

РАЗДЕЛ 4. МЕТОДЫ М18–М21 (предложены СС) — ВЕРДИКТЫ И УТОЧНЕНИЯ ПО ДАННЫМ

--------------------------------------------------------------------------------
4.1. М18 «Тепловой баланс Т/О и печей» — ПРИНЯТЬ, данные есть.
--------------------------------------------------------------------------------
Данные подтверждены в эталоне: печать Т/О содержит «KF=…; Контур 1: T1(1)=…
T1(2)=…» (контуры с температурами, кerr-маркер −5xx-семейство); печи —
F(т.газа)/T(сгор.)/kig/Q(полн.) + КОНТУР N — Q есть ПРЯМО в печати.
Расходы контуров — из «расходы:» (нормализованные, «+ = приток»). Уточнения:
  - Q = F·Cp·ΔT: Cp зависит от состава. Первый шаг — ОТНОСИТЕЛЬНЫЙ критерий:
    dQ = |Q1−Q2|/max(Q1,Q2) > порог (настройка, дефолт 30% — согласен с СС) И
    проверка знака физики (холодный контур греется без горячего источника → Fail).
  - Считать по ПЛАТО (несколько сканов), не по одному — иначе шум.
  - Учесть «0.00»-порог печати (ZeroPrintEps, п. 1.1) и REG-фактор Т/О.
  - Печи: сверка Q(полн.) печати с Σ тёплых нагрузок контуров — отдельная проверка.

4.2. М19 «Якоби/время цикла» — ПРИНЯТЬ ПО СУТИ, ПЕРЕИМЕНОВАТЬ.

4.3. М20 «Узкие места» (K_гидр = F²/ΔP) — ПРИНЯТЬ С ОГОВОРКОЙ ПО ФОРМУЛЕ.
--------------------------------------------------------------------------------
ΔP ребра = P_A − P_B (карточки); D/L/io — из «связи_2:» и юнитов. НО:
проводимость в м2 задаётся через U_ri/KU2_r (проходимость), а не чистой
геометрией — «теоретический K по D/L» надо строить по формуле, которую реально
использует м2 (уточнить по коду FR_C/PressM2Tube — НЕ выдумывать формулу).
Практический первый шаг без формулы: ранжирование рёбер по «аномальный ΔP при
малом F при живом U_ri» (противоречие — семейство М16) — это и есть «висячие
перепады». Сравнение с D/L — отдельная сверка с юнитами. Пороги — в Settings.
Не обещать в руководстве больше, чем реализовано.

4.4. М21 «Верификация уставок/защит» — ПРИНЯТЬ, формат подтверждён по коду.

РАЗДЕЛ 5. НОВЫЕ МЕТОДЫ (предложение ассистента — поверх М18–М21)

HEALTH-вывод в ТОМ ЖЕ скане (не «залип» из прошлого) и что при норме молчит;
нарушение закона = находка (дефект законности оповещений конверторов).
Источники: события HEALTH (−779/−778 Б У И/У И; −790..−798 стражи LH1;
−800..−807 CG4) + kerr-события; окно = скан.

узел×скан); скан без карточек узлов = обрыв печати; «узел пропал и НЕ вернулся»
= выселение из схемы с находкой (сейчас только DQ «исчезнувшие узлы» — усилить
периодичностью и «никогда не вернулся»).

должен топиться в сотне находок.

РАЗДЕЛ 6. РАЗВИТИЕ: СЛОЙ 5 «ИНЖЕНЕРНЫЙ ПОДСКАЗЧИК» (главная рекомендация)

Архитектура: слой 5 поверх слоя 4 (диагностика). Вход: находки М1–М25 + дерево
кейсов К01–К17 + индекс kerr→код + реестр арматур + контуры + паспорт.

6.1. БАЗА ПРИЧИН «сигнатура → известный дефект → проверка в коде».
Наполняется из ИСТОРИИ ФИКСОВ генератора/конверторов (ПСР, журнал FIX11.10.x,
реестр lh3_fix_registry) — у нас есть проверенные паттерны с причинами
(см. раздел 7.2). Каждая строка базы: код-сигнатура → типовой дефект →
блок юнита → шаблон исправления → как проверить.

6.2. «Билет на исправление» — прямой выход на процесс владельца.
Кнопка на «Диагностике»: «Сформировать задачу для исполнителя» — диагностика
превращается в САМОДОСТАТОЧНЫЙ файл задачи (конвенция КП4/С.С.: описание
проекта с начала + ровно следующий шаг + якоря кода: файл, процедура, строка
kerr, дословный фрагмент). Это встраивает анализатор в существующий процесс:
находка → файл задачи → С.С. правит → приёмка владельцем.

6.3. Диалоговый режим подсказчика.
«Спросить подсказчик» — свободный текст симптома от оператора → матч по дереву
симптомов (словарь синонимов уже есть в NLG-слое) → ответ с ветвями:
«если так — это, если так-то — это» (формат владельца от 01:24 28.11).
Каждая гипотеза — с вероятностями и ссылкой на строку юнита.

6.4. Обучаемость подсказчика.
Вердикты владельца (precision/recall уже считаются) обновляют вероятности ветвей;
новые ветки и кейсы добавляются без правки ядра (перфокарты/кейсы в KtkData).
Список «НЕ ВНОСИТЬ» (известные допустимые дефекты, как CG4 GROFF/GR_rep) —
фильтр KnownDefects расширяется декларативно.

6.5. Маркировка.
Любая гипотеза подсказчика — с пометкой «ОЦЕНКА — не расчёт м2» (правило ТЗ
«Граф» 40/41). Авторитет проверки — реальный м2-прогон.


РАЗДЕЛ 7. МЕТОДИКА ПОИСКА ОШИБОК (подробный сценарий для анализатора — что,

--------------------------------------------------------------------------------
7.0. Принцип: анализатор ищет не «что-то странное», а КОНКРЕТНЫЕ СИГНАТУРЫ
     известных дефектов — с готовой локализацией в коде.
--------------------------------------------------------------------------------
Цепочка локализации (конвейер метода → билета):
  симптом в логе → первый скан аномалии → kerr-код → (юнит, строка, блок) →
  типовой дефект из базы причин → строка юнита (kerr ±10) → гипотеза/исправление →
  как проверить после исправления.

7.2. БАЗА ТИПОВЫХ ДЕФЕКТОВ (сигнатура в логе → причина → как искать).
Накоплена по реальным фиксам генератора и конверторов:

  СГ1. «Локаль Val()» (фикс генератора 11.10.15).
    Сигнатура: KGS=0 / AK_=0 / NAB_=0 у узлов с кранами; ARMV не напечатан;
    суммы нулевые при открытых арматурах.
    Причина: Val() в VBA всегда ждёт точку; ячейки-числа Excel дают строку с
    запятой (русская локаль) → старый NumVal2 возвращал 0.
    Как искать: М-метод «нулевые KGS/AK_/NAB_ при открытых кранах» (частично
    покрывается М16); в юните проверять наличие лексемного NumVal2/IsNum2.

  СГ2. «Конвейер aa3» (фикс генератора 11.10.16).
    Сигнатура: GTc узла НЕ равен сумме входящих расходов; Tc рушится за 1 тик
    (пример: истина aa3=1.19, мусор aa3=14.02 → Tc с 20 до мусора за скан).
    Причина: классовое поле aa3 — конвейер расходов (FR_C затирает его расходом
    каждой связи), а Т-блок копил в него же сумму входящих.
    Как искать: НОВОЕ правило для анализатора: сверка «GTc узла vs Σ|Fc| входящих
    нормализованных связей» с допуском % — отдельная находка (кандидат: расширение
    М1 или новый М26); плюс триггер «Tc падает аномально быстро».

  СГ3. e27-заменители и нулевые связи.
    Сигнатура: расход «0.00» при активной связи (U_ri ≠ 0, арматура открыта) —
    заглушка/нулевая проводимость; «0.00» при закрытой арматуре — норма.
    Как искать: уже М12/М16 (порог 0.02 — печатный ноль, см. 1.1);
    дополнить сверкой с «условиями:» и степенью арматуры.

  СГ4. Механика давлений/гидроудар (фикс генератора 11.10.20, PressM2Tube/App).
    Сигнатура: экспоненциальный разгон p (пример: tr130 10.36→829 ати за 8 мин);
    T рушится до −3000°C; расходы вдоль линии разъезжаются.
    Причина: старый м4-интегратор tgt=(p+dt0·(Sin−Sout))/C_i; удалён, заменён
    м2-методом 2 с релаксацией, K_v-сглаживанием, PhClamp, гидроударом.
    Как искать: М8/M9/M11 уже ловят родственные сигнатуры; ДОБАВИТЬ отдельный
    триггер «Tc < −273» (физически невозможная температура — мгновенный Fail).

  СГ5. Стражи LH1 (−790..−798) и LH3-вставки (−961..−963).
    Сигнатура: NaN/бред, вне диапазона, freeze; частые клампы объёма/разбавления =
    расход/объём за пределами; «NON STOP kerrs» (−785) = Miss_work пуст.
    Как искать: М6 уже группирует; ДОБАВИТЬ частотный профиль: рост частоты
    стражей во времени (перед «штормом») — ранний предвестник.

  СГ6. Спам лога / известные дефекты печати CG4.
    Сигнатура: GROFF=0, GR_rep без сброса — выводы v16-эры; лечится перегоном
    на актуальных конверторах.
    Как искать: фильтр KnownDefects уже понижает до ИНФО; следить, чтобы
    понижение НЕ маскировало рост частоты (считать частоту до понижения).

  СГ7. «Защёлка Miss_ind» (М15) — процедуры молча исчезают из расчёта
    (нет SUCSESS-штампов). Связка с «NON STOP kerrs».

  СГ8. Обрыв журнала / шторм стражей (М10): 9960 строк из 10000 за 5 с —
    дефект ЖУРНАЛА, не модели (сейчас реализовано — не трогать).

  СГ9. Дрейф Ps БУИ (М7/К01): плавный монотонный — данные заказчика неверны;
    скачками — реакция на арматуру. Направление диагностической ветки
    («гипотеза → данные заказчика» vs «гипотеза → манипуляции») — реализовано.

  СГ10. Пресеты/зеркала: симметрия 152/212 (М1) — «небьющиеся условия связи»
    зарезервированы, НЕ реализовывать без команды владельца (решение 28.11).

7.3. ПОШАГОВЫЙ АЛГОРИТМ ЛОКАЛИЗАЦИИ (заложить как конвейер «симптом → код»):
  Шаг 1. Нормализация журнала; карта сканов (время, D3-индекс, режим RUN/DEBUG,
         паспорт: MAIN_c, SK_L, LIM_P, версия комплекта, штамп юнитов).
  Шаг 2. Сбор событий: kerr-строки (код+контекст), стражи LH1/CG4/LH3,
         SUCSESS/Miss_work, AI_Comments («ошибка давления/температуры»),
         HEALTH-панели (Б У И/У И), ВРЕМЯ цикла.
  Шаг 3. По каждой находке M-метода: «первый скан аномалии» + окно (плато/дрейф/
         шторм) — время до/после (иерархия первопричин слоя 4).
  Шаг 4. Локализация: kerr-код → (юнит, строка, блок) по индексу → типовой
         дефект из таблицы 7.2 → соседние узлы (по связям/контуру) для
         подтверждения (паттерн распространяется по сети от корня).
  Шаг 5. Проверка гипотезы в юните: «Найти в коде» — строка вокруг kerr ±10;
         паттерн-сверка: Val/локаль (СГ1), конвейер aa3 (СГ2), e27 (СГ3),
         PhClamp/гидроудар (СГ4), V_ri-направление и знак, clamp-семейство.
  Шаг 6. Вывод «билета на исправление» (см. 6.2): узел/связь, сканы, найденный
         паттерн, строка юнита, что чинить, как проверить (эталон, счётчики,
         перегон конверторов К1/К2/К4).
  Шаг 7. Обучение: вердикт владельца → обновление вероятностей ветви;
         ложные срабатывания → игнор-лист; новые паттерны → перфокарта без кода.

7.4. Контроль целостности самого анализа (чтобы не ловить фантомы):
  - сверка конвенции знака на зеркальной паре (инвариант из 1.3) перед любым
    численным методом;
  - DQ-гейты (обрезка журнала, разрывы времени, доля нераспознанного) — уже есть,
    держать ПЕРЕД численными методами;
  - SAFE MODE без паспорта — уже есть; дополнить проверкой версии юнитов (М25).
