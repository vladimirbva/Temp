# КП4 — РАБОТА С AI-АССИСТЕНТОМ CLAUDE CODE (CC)

**Версия:** 1.0 (25.11.2026, по указанию владельца).
**Назначение:** контур взаимодействия основного ассистента с внешним AI-ассистентом
Claude Code (далее — CC). Запускается ТОЛЬКО по явной команде владельца
(«КП4», «КП4.1» и т.п.); самопроизвольно не инициировать.

---

## 4.1. Постановка задачи CC

### Роли и схема
- **Ассистент (основной)** — постановщик задач, ГЛАВНЫЙ АУДИТОР и СБОРЩИК итога.
- **CC** — исполнитель: формирует/правит код по задаче; доступа к файлам владельца
  у него НЕТ.
- **Владелец** — только канал пересылки: принимает файл задачи от ассистента и
  пересылает его CC, ответ CC пересылает обратно ассистенту. Из содержательной
  схемы владелец исключён.

### Файл задачи
- Выдаётся ассистентом отдельным файлом (карточкой в чат) с ОТДЕЛЬНЫМ номером
  запроса и признаком темы работы в имени файла.
- В верхних строках файла номер запроса дублируется текстом (пример вида
  «код исправления 31f…»); далее — сам запрос для CC.
- Файл САМОДОСТАТОЧЕН: CC каждый раз открывает его как новый чат в новом
  контекстном окне, обращение к внешней библиотеке/файлам владельца невозможно.
  Поэтому в задачу включается:
  1) описание проекта С НАЧАЛА (что за проект, где стоит, что сделано, текущая
     архитектура и ограничения);
  2) задача по формированию кода — РОВНО СЛЕДУЮЩИЙ шаг по утверждённому плану
     PSR.
- Запрос НЕБОЛЬШОЙ: задача на ОДИН ход. Несколько спринтов сразу в одной задаче —
  ЗАПРЕЩЕНО.

### Прогоны
- При работе по КП4.1 обязательные смоуки/прогоны СО СТОРОНЫ ВЛАДЕЛЬЦА в задачу
  не включаются — эти шаги пропускаются. Контроль качества выполняет ассистент
  аудит-ответом и общим циклом КП.

### Вопросы к владельцу
- Если у ассистента есть вопросы к владельцу, они в первую очередь прописываются
  в задаче для CC со стандартной формулировкой:
  «Есть вопрос для Владельца: <вопрос>. Если ты готов принять за него решение,
  и оно однозначное, то Владелец согласовал это и просит принять решение тебя».
  CC отвечает/принимает решение; владелец пересылает ответ ассистенту.

### Ответ CC и аудит
- Ответ CC владелец пересылает ассистенту. Ассистент ПОДВЕРГАЕТ ОТВЕТ АУДИТУ:
  сверка с планом PSR, кодом/эталонами, полнотой, стилем и форматом.
- Найдены вопросы или нестыковки — ассистент ОБЯЗАН задать их на СЛЕДУЮЩЕМ ходу
  (не замалчивать и не править молча). Все решения — по обоюдному согласованию
  ассистента и CC (пересылка — через владельца).
- Ассистент — ГЛАВНЫЙ АУДИТОР И СБОРЩИК: принятый результат он собирает в общий
  цикл проекта (full_code/PSR и т.п.) по соответствующим командам КП.

### Итог каждого хода (жёстко, добавлено владельцем 25.11.2026)
- КАЖДЫЙ ход работы по КП4.1 завершается выдачей РОВНО ОДНОЙ карточки —
  full_code.txt: ПОЛНАЯ сборка кода одним файлом (журнал фиксов в шапке,
  явные заголовки «=== ФАЙЛ: имя ===», всегда актуальная база).
- Одновременно ассистент кладёт в хранилище (проектная папка) ОБНОВЛЁННЫЙ PSR:
  актуализированный (история дописана, СЕЙЧАС и ПЛАН обновлены). Карточкой PSR
  не выдаётся — только по прямому запросу владельца.

### Сопутствующие правила
- Действуют КП5 (экономия времени), каналы выдачи (карточка в чат — приоритет),
  манифест выдач и точка входа проекта (КП5.4–5.5).
- Задачи для CC и ответы CC хранить в проектной папке хранилища: текущая серия +
  1–2 предыдущие, старое — по ротации хранилища.

## 4.2. Глобальный вопрос CC (математико-архитектурная тема)

**Версия:** 1.1 (26.11.2026, по указанию владельца).

### Назначение
- Формат постановки ГЛОБАЛЬНОГО вопроса для CC — НЕ на код и кодовые решения,
  а на математико-архитектурную тему: постановки методов, схемы решателей,
  численные схемы, разборы физики/структуры расчёта, выбор архитектуры модулей.
- Цель — получить от CC содержательную экспертизу/обоснованный ответ, а не подгонку
  кода по багам. Подгонка кода по багам — остаётся в ведении КП4.1.

### Что сохраняется от КП4.1
- Роли (ассистент — постановщик/аудитор/сборщик; CC — исполнитель; владелец — канал
  пересылки).
- Файл задачи: отдельный файл-карточка с отдельным номером запроса и признаком темы
  в имени; номер дублируется текстом в верхних строках.
- Полное изложение: описание проекта С НАЧАЛА — самодостаточность обязательна (CC
  в новом контекстном окне).
- Аудит ответа ассистентом; вопросы/нестыковки — на следующем ходу; решения — по
  обоюдному согласованию (пересылка через владельца).
- Действуют КП5 и каналы выдачи; хранение задач/ответов CC — в проектной папке
  (текущая серия + 1–2 предыдущие).

### Отличия от КП4.1
- Вопрос ГЛОБАЛЬНЫЙ: сформулирован как математическая/архитектурная постановка
  (что именно спрашивается, какие альтернативы, какие критерии выбора), а не как
  инструкция по правке конкретных строк кода.
- Формат ответа: содержательное обоснование (схема, формулы, критерии, риски,
  ограничения) — код по задаче НЕ является обязательным результатом; если CC
  приводит код как иллюстрацию схемы, он считается иллюстрацией, не deliverable.
- Задача всё равно на ОДИН ход; несколько глобальных вопросов в одной задаче —
  ЗАПРЕЩЕНО.
- Итог хода: карточка ответа на глобальный вопрос (разбор ассистента + выдержки
  ответа CC) в чат; сборка в общий цикл проекта — по необходимости и по команде.
- Смоуки/прогоны со стороны владельца по КП4.2 не запрашиваются (как в КП4.1).

## Суффикс «г» — выкладка файла задачи на ГВР (КП4.1г / КП4.2г)

**Добавлено владельцем 26.11.2026; уточнение о регистре и алфавите — 26.11.2026.**

- Если владелец пишет команду с суффиксом «г» (КП4.1г / КП4.2г), файл задачи
  выкладывается на ГВР — временный репозиторий GitHub vladimirbva/Temp
  (см. rules/gvr_temp_repo_v1.md).
- Форма записи суффикса НЕ важна: «г», «Г», «g», «G» — все означают одно и то же
  (выкладка на ГВР). Команды владельца в целом распознаются в ЛЮБОМ регистре и в
  обеих раскладках/алфавитах (рус/лат), если из текста не следует иное.
- Папка на ГВР называется ПО ИМЕНИ ПРОЕКТА, БЕЗ ЦИФР (как имя проекта в актуальной
  записи: BUDcad, TecHet, Pinchess, PlanetCraft и т.п. — без номеров версий и
  суффиксов). Папки нет — создать. Файл кладётся в корень этой папки или во
  вложенную, по месту проекта.
- Комплект выдачи НЕ меняется — остаётся как в классических КП4.1 / КП4.2
  (для КП4.1: карточка full_code + обновлённый PSR в хранилище; для КП4.2: карточка
  разбора). ГВР — дополнительный канал выкладки файла задачи.
- В ШАПКЕ сообщения для CC (верхняя часть файла задачи) ОБЯЗАТЕЛЬНО указывать:
  какой файл, с каким именем и в какую папку (корневую или вложенную) записан на
  ГВР — чтобы CC мог прочитать файл задачи из репозитория.
- Неоднозначность имени папки — одним коротким уточнением, не догадкой.
