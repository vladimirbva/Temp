# СВОД ПРАВИЛ РАБОТЫ ПО КП — КОМАНДНЫЙ ПРОТОКОЛ v1.0

**Дата:** 24.11.2026
**Назначение:** сводный документ по всем введённым владельцем командам КП (КП1, КП2, КП3, КП5) —
для непрерывной работы ассистента в любом чате. Источник истины: формулировки владельца.

---

## 0. БАЗОВОЕ: КАК РАСПОЗНАЮТСЯ КОМАНДЫ

- Команда владельца — явная надпись вида «КП1», «КП1.2», «КП3.1» и т.п. В теле текста,
  без этого, ассистент НЕ поднимает КП сам.
- Если в сообщении владельца есть формулировка-приглашение к действию, содержащая смысл
  команды (например «сделай полный план»), ассистент может предложить соответствующий КП,
  но запускает только после явного подтверждения владельца.
- Форматированное упоминание «#КОМД» («#комд») — всегда принимает статус команды.
- Приоритет: 1) #комд; 2) явная текстовая команда; 3) содержательный смысл. Если явной
  команды нет — НЕ творить по умолчанию.

## 0.1. БАЗОВОЕ: СТАТУСЫ ПРОЕКТОВ

- Статусы по каждому проекту ассистент ведёт в памяти:
  [ПАУЗА] — работа приостановлена, вернёмся позже;
  [АКТИВ] — активная работа (вести полный поток статусов в конце каждого хода);
  [ФИНАЛ] — работа завершена и закрыта;
  [СТОП] — отложено до полной очереди (может иметь подпись причины);
  [ПОЛУФИНАЛ] — основная часть сделана, идёт доработка (в конце очереди АКТИВ).
- Если по проекту ничего не велось — статус не меняется.
- Полный цикл: [ПОЛУФИНАЛ] → [ФИНАЛ]. Смена статуса на [ФИНАЛ] — только по указанию владельца.
- Прерванная/незавершённая работа: [АКТИВ][ПОЛУФИНАЛ] или [АКТИВ][СТОП] с детализацией.
- Реактивация [СТОП]/[АКТИВ][СТОП] — только по явной команде владельца.

## 0.2. БАЗОВОЕ: ФОРМАТ ОТЧЁТА О ХОДЕ (при активной работе)

- В конце хода при [АКТИВ]: СДЕЛАНО (последний шаг), ТЕКУЩЕЕ (что на ходу), NEXT (следующий шаг).
- Новые материалы/правки владельца отражать ТОЧНО и ПОЛНО, без пересказа по памяти.

## 1. КП1 — КОМАНДА ПРОЕКТА (спринтовый цикл)

**Назначение:** короткий штурм-цикл «обсудить → план → сделать → сдать» по ТЕКУЩЕЙ точке плана
PSR проекта. Владелец пишет «КП1» (опционально «КП1: <тема>»), ассистент выполняет цикл.

### Шаги
1. Точка плана: берётся СЛЕДУЮЩАЯ точка по утверждённому плану PSR (если владелец не указал иную тему).
2. Постановка: коротко сформулировать, что делаем на этом спринте (цель, границы, критерий готовности).
3. Работа: сделать нужные шаги (код/документы/расчёты — по сути точки плана) с САМОПРОВЕРКОЙ.
4. Самопроверка: чек-лист по критерию готовности + инварианты проекта (ошибки — на месте).
5. Сдача: выдача результата владельцу + указание изменения PSR (если есть).

### Ограничения
- За один ход КП1 — РОВНО ОДНА точка плана.
- Если цель точки не ясна — СНАЧАЛА краткий вопрос владельцу, потом работа.
- КП1 не заменяет КП2/КП3 — это обычный спринтовый шаг.

---

## 2. КП1.1 — ПОЛНАЯ СБОРКА ИТОГА (full_code.txt)

**Назначение:** собрать ПОЛНУЮ актуальную сборку итогового кода проекта ОДНИМ ФАЙЛОМ.
Владелец пишет «КП1.1», ассистент выдаёт full_code.txt.

### Шаги
1. Собрать актуальное состояние кода (все правки, журналы фиксов, актуальная база).
2. Оформить ОДИН файл full_code.txt: заголовки «=== ФАЙЛ: имя ===», в шапке — журнал фиксов.
3. Файл «чистый»: без обрывов, без дублей секций, с явными границами файлов.
4. Выдача: ОДНА карточка full_code.txt. Доп. пояснения — текстом в чат, не в файл.

### Ограничения
- Собирать ИЗ АКТУАЛЬНОЙ БАЗЫ, не «по памяти».
- Если сборка объёмная — предупредить владельца о размере ДО выдачи.

---

## 3. КП1.2 — ТЕСТОВЫЙ ПАКЕТ (test_pack.txt)

**Назначение:** собрать ПОЛНЫЙ пакет тестов к текущей сборке ОДНИМ ФАЙЛОМ.
Владелец пишет «КП1.2», ассистент выдаёт test_pack.txt.

### Шаги
1. Тесты строятся под ПОСЛЕДНЮЮ сборку (после последнего КП1/КП1.1).
2. Состав: все актуальные тесты (смок-тесты, инварианты, тесты новых фич).
3. Оформить ОДИН файл test_pack.txt с заголовками «=== ФАЙЛ: имя ===» и шапкой-описанием.
4. Выдача: ОДНА карточка test_pack.txt.

### Ограничения
- НЕ включать устаревшие тесты — только актуальные.
- Промежуточные тесты «на ходу» — КП1.3.

---

## 4. КП1.3 — ПРОМЕЖУТОЧНЫЕ ТЕСТЫ (быстрый пакет)

**Назначение:** быстро дать МАЛЫЙ пакет тестов «на ходу» (10–40% целевого объёма).
Владелец пишет «КП1.3», ассистент выдаёт мини-пакет.

### Шаги
1. Взять ключевые точки текущего шага (что меняем / что могло сломаться).
2. Дать 10–40% целевого пакета: важные тесты инвариантов + смок-тесты новых частей.
3. Оформление: один файл или серия коротких файлов, БЕЗ широкой обвязки.
4. Выдача: карточка(и) + одна строка «что этот пакет проверяет».

### Ограничения
- КП1.3 — НЕ замена полному пакету (КП1.2) и НЕ замена приёмке.
- Повторять можно по каждому ходу — по запросу владельца.

---

## 5. КП1.4 — ПРЕЗЕНТАЦИЯ ИННОВАЦИЙ (сводная карта по направлениям)

**Назначение:** подготовить ПОЛНУЮ сводную презентацию/документ по инновациям всех направлений проекта.
Владелец пишет «КП1.4», ассистент выдаёт сводный файл.

### Шаги
1. Сбор по каждому направлению: ключевые инновации, уровни готовности, вклад в цель.
2. Сводная структура: секция на направление; внутри — инновации, эффект, готовность.
3. Оформление: единый документ/презентация с оглавлением.
4. Выдача: ОДНА карточка сводного файла.

### Ограничения
- По каждой инновации — что делает, в чём эффект, статус готовности (без «названий»).
- Объём секции — до 1–2 страниц, без «воды».

---

## 6. КП2.1 — ГЛОБАЛЬНЫЙ ТЕХНИЧЕСКИЙ ПЕРЕСМОТР

**Назначение:** пересмотреть ВСЮ текущую сборку «глазами свежего человека»: логика, структура,
риски, несоответствия. Код НЕ меняется — только разбор.
Владелец пишет «КП2.1», ассистент выдаёт отчёт.

### Шаги
1. Прочитать/просмотреть текущую сборку (все основные модули; объёмно — по списку).
2. По каждому модулю: логика, структура, соответствие плану PSR, риски, несоответствия.
3. Отчёт: по модулям + общая оценка + список замечаний (по приоритету).
4. Выдача: отчёт в чат (или карточкой, если объёмный).

### Ограничения
- КП2.1 НЕ меняет код; правки — по команде владельца (обычно КП1-циклом).
- Непроверяемое без запуска — явно пометить «нужен прогон».

---

## 7. КП2.2 — РАЗБОР ДИСКУССИИ И РЕШЕНИЙ

**Назначение:** разобрать вопрос/дискуссию владельца: варианты, за/против, критерии, риски,
рекомендации. Владелец пишет «КП2.2» + текст вопроса, ассистент выдаёт разбор.

### Шаги
1. Формулировка вопроса: повторить чётко (зафиксировать предмет).
2. Разбор: варианты решения, за/против, критерии выбора, риски.
3. Вывод: рекомендуемый вариант + условия, при которых он верен.
4. Выдача: разбор в чат (до 1–2 страниц).

### Ограничения
- НЕ «продавливать» мнение: показывать альтернативы; вывод — с обоснованием.
- Решение принимает владелец.

---

## 8. КП3.1 — ПОЛНЫЙ ПЛАН ПРОЕКТА (создание PSR)

**Назначение:** создать/пересобрать ПОЛНЫЙ план проекта PSR.
Владелец пишет «КП3.1», ассистент выдаёт полный план.

### Шаги
1. Сбор информации: цели, этапы, готовое, ограничения, пожелания владельца.
2. Структура: этапы/фазы, внутри — задачи с критериями готовности.
3. Оценки объёма: по каждой задаче — приблизительный объём, зависимости.
4. Оформление: файл PSR («Полный план»), с датой сборки.
5. Выдача: карточка файла плана.

### Ограничения
- План — ПОЛНЫЙ и САМОДОСТАТОЧНЫЙ, без ссылок «как обсудим».
- Правки после выдачи — только через КП3.2 или новый КП3.1.

---

## 9. КП3.2 — ПОДСТРОЙКА ПЛАНА PSR (точечная правка)

**Назначение:** точечно изменить текущий план PSR без полной пересборки.
Владелец пишет «КП3.2» + что меняется, ассистент правит PSR.

### Шаги
1. Локализовать изменение: какой этап/задача/срок меняется.
2. Правка PSR: заменить/добавить/удалить; проследить зависимости.
3. Выдача: обновлённый PSR (полный) или точечная выписка — по объёму правки.
4. Отчёт: что изменилось, на что повлияло.

### Ограничения
- Правка более ~30% плана — предупредить владельца, предложить КП3.1.

---

## 10. КП5 — ЭКОНОМИЯ ВРЕМЕНИ И РЕСУРСОВ

**Назначение:** НАБОР ПРАВИЛ экономии времени и ресурсов при работе по любым КП. Действует
ПОСТОЯННО, не требует вызова. Полный текст — KP5_time_economy_v1.md.

### Краткая суть
1. КП5.1 — окружение песочницы: SDK/окружение — ОДИН РАЗ в постоянное хранилище;
   восстановление копированием, скрипт-восстановитель.
2. КП5.2 — тесты: промежуточно 10–40% (КП1.3); полный пакет — финал/КП1.2/приёмка.
3. КП5.3 — отладка: мини-сцена первой, зонная трассировка, инвариант-чекеры, снапшоты,
   headless до UI.
4. КП5.4 — файлы: якорное чтение; предфлайт-якоря; патчи более 3–5 мест — с dry-run;
   манифест выдач; ротация; выдача сжато.
5. КП5.5 — планирование ходов: разведка батчами; инкрементальные сборки; тяжёлое — после карточек;
   точка входа «start_here»; один срез истины.
6. КП5.6 — при противоречии: явная команда владельца выше всего.

## 11. ПРИОРИТЕТЫ ПРАВИЛ

1. Явная команда владельца — выше всего.
2. КП1/КП2/КП3 — ЧТО и В КАКОМ СОСТАВЕ делается (состав выдачи).
3. КП5 — КАК достигается результат (способ, экономия времени).
4. КП4 — отдельно: взаимодействие с внешним AI-ассистентом (CC).
