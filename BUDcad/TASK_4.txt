Технолог Дима прислал два замечания с рисунками; ассистент сверил с кодом. Диагнозы ниже — ПРОВЕРЕННЫЕ.

Замечание 1 (скрин «Рисунок 1.1_пинч»): окно пинч-анализа открывается так, что кнопка
«Загрузить из клешё…» невидима; при растяжении окна появляется. Горизонтальный скроллбар внизу
«двигает только таблицу».
КОДОВАЯ ПРИЧИНА (проверено): PinchStudio.BuildStreamsTab: панель кнопок = FlowLayoutPanel
{ Dock=Top, Height=48, FlowDirection=LeftToRight, Padding(8,8,8,4) }, WrapContents=true по
умолчанию. Кнопки: ＋ Поток (AutoSize), Удалить выбранный, Демо-пример, Из расчёта схемы
(Width=170), Клешё → Excel… (Width=150), Загрузить из клешё… (Width=175), Label «Часов/год:» +
NumericUpDown (Width=72). Сумма ширин ~900+ при старте окна Size(980,660) — на грани;
при DPI>100% или узком окне кнопки переносятся на вторую строку, которая ОБРЕЗАЕТСЯ фиксированной
Height=48. Скроллбар принадлежит DataGridView (_gridStreams) — панель кнопок не скроллится.

Замечание 2 (скрины «Рисунок 1.1_таргетинг_10/20/100%»): при ΔTmin=10/20/100 композитные кривые
«лежат на линии или гарантированно соприкасаются»; по Диминому ожиданию (учебник) кривые должны
сближаться в одном месте. КОДОВАЯ ПРИЧИНА (проверено): НЕ ДЕФЕКТ РАСЧЁТА.
PinchEngine.Target: интервалы в сдвинутых координатах sh=ΔTmin/2; BuildComposites: HotCompT = Ts−sh,
ColdCompT = Ts+sh; PlotPaint — единая физическая ось X (xOf от hMin..hMax), холодная кривая
сдвинута влево на CompOffset=−QHmin: зазор между кривыми на ЛЮБОМ уровне ≥0, В ПИНЧЕ = 0
(касание — это норма сдвинутого таргетинга), у верха = QHmin, у низа = QCmin. PinchShifted —
пинч по сдвинутой температуре; PinchHot=pinch+sh, PinchCold=pinch−sh.
Скрины подтверждают корректность: ΔTmin=10→Q_нагр/Q_охл=10/10 (пинч 50/40 °C), 20→20/20,
100→220/220; Q растёт с ΔTmin, баланс сходится. Ожидание Димы соответствует НЕсдвинутому
представлению (зазор в пинче = ΔTmin). Дефект — отсутствие объяснения в UI, не математика.

A. Замечание 1 (Сп0, быстрый фикс):
   1. Панель кнопок вкладки «Потоки»: сделать резиновой к переносу — AutoSize=true +
      AutoSizeMode=GrowAndShrink (Dock=Top сохраняется), ЛИБО два фиксированных ряда, ЛИБО
      WrapContents=false с собственным скроллом панели. Выбери и обоснуй (минимум сюрпризов).
   2. Стартовый размер окна по содержимому: MinimumSize/ClientSize так, чтобы при 100% и 125%
      DPI обе строки кнопок были видны; проверить вкладки «Таргетинг»/«Сеть» на ту же ошибку
      (инвентаризация кнопочных панелей PinchStudio и дочерних окон).
   3. Прогнать сборку: 0 ошибок/предупреждений; существующие эталоны зелёные (UI не затрагивается).
B. Замечание 2 (фрагмент Сп2, без трогания PinchEngine):
   1. На графике «Таргетинг» — пояснительная подпись/подсказка: «оси сдвинутые: горячая −ΔTmin/2,
      холодная +ΔTmin/2; касание в пинче — норма; зазор у верхнего края = QHmin, у нижнего = QCmin».
   2. Добавить переключатель «Оси: сдвинутые / фактические»: в фактических — обе кривые без сдвига
      (HotCompT, ColdCompT−? : фактические T, сдвиг по X тот же), зазор в пинче = ΔTmin, и при
      визуальном пересечении — предупреждение «пересечение = нарушение ΔTmin».
      Пересчёт не нужен — это только ОТРИСОВКА (PlotPaint), данные те же.
   3. Термин «клешё» заменить на «кейс» в подписях кнопок/сообщениях (опционально, owner —
      если сомневаешься, пометь вопросом).
С. Ограничения: ядро PinchEngine/PinchDesign/эталоны НЕ трогать; правило паритета; InvariantCulture;
   тёмная тема через существующие константы PinchStudio (ThemeManager-централизация — Сп0, но в этой
   задаче не распыляться: только сформулируй, если заметишь).
