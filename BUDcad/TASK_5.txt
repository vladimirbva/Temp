TASK_5 (КП4.1, этап 1 спринта Сп1) — BUDcad: единый HEN layout-движок для сетчатой диаграммы
Номер запроса: 5 · Тема: BUDCAD-SP1-HEN-LAYOUT · Тип: проектирование архитектуры + план переноса (код — следующий ход)
Дата: 26.11.2026

========================================================================
1. КОНТЕКСТ
========================================================================
BUDcad 2.2 (WinForms, .NET 8) — симулятор технологических схем: гидравлика+тепло+составы,
решатель по тикам, сцены в JSON. Полный код r42 у тебя в контексте («код 42», 3 217 686 Б);
сборка r43 собрана ассистентом из твоего дифа по TASK_4 (правки: резиновые кнопочные панели
PinchStudio/PinchGridWindow, размеры окна, переключатель «сдвинутые/фактические оси» в
PlotPaint) — на Сп1 не влияет. База для Сп1 — r43 (sha1 4cb0ad34…; отличия от r42 — только UI-панели).

Решения владельца (приняты, PSR BUDcad):
• Р-17: сетчатая диаграмма — сетка Линнхоффа, ось X = накопленная тепловая нагрузка.
• Р-18: документ-вкладки Схема|Пинч|Отчёт|Журнал + докируемый пинч; PinchGridWindow сохраняется.
• Порядок спринтов: Сп0 (готово, вошло в r43) → Сп1 (этот) → Сп2 (UX пинча) → Сп3 (вкладки) → Сп4.

Твой диагноз из TASK_2 (принят):
• два расходящихся рендера сетчатой: inline GridPaint в PinchStudio и PinchGridWindow — без
  единой физической оси X; геометрия вычисляется прямо в Paint; масштаб от размера панели;
• следствие: при изменении размеров окна картинка «плывёт», подписи наплывают, пользователь
  не может доверять диаграмме.

========================================================================
2. ЗАДАЧА (этап 1: архитектура, БЕЗ кода-дифа)
========================================================================
Спроектируй этап 1 Сп1 — «чистый layout-движок»:
1. HenLayoutModel: чистая структура данных сетчатой в МИРОВЫХ единицах, вычисляемая ОДИН раз
   из PinchDesign (полосы потоков по ветвям, аппараты на пересечениях гор./хол. ветвей, утилиты,
   подписи с мировыми прямоугольниками, коллизии подписей решаются В layout-проходе, не в Paint).
2. Одна функция единица→пиксели (transform: мир→канва) — единственный доступ к масштабу.
3. ОДИН рендерер: PinchGridWindow-рендерер становится единственным; inline GridPaint в
   PinchStudio либо удаляется, либо делегирует на тот же рендерер (обоснуй выбор);
   RenderForReport переходит на рендерер (экспорт PNG/PDF сохраняется: F11 весь экран,
   Ctrl+S PDF, зум/панорама — не теряются).
4. Ось X — накопленная тепловая нагрузка (Р-17): укажи, откуда в PinchDesign берётся
   накопленная нагрузка для позиционирования аппаратов и что делать, если она отсутствует.
5. Golden-image эталоны: как снимать (фиксированные сцены, детерминированный рендер при
   фикс. канве), где хранить, как сравнивать в автоматике; минимум 3 сцены (демо-пинч,
   схема с 2 аппаратами, схема с переносом через пинч).

Формат ответа:
1) Эскиз API HenLayoutModel (структуры, поля, функции, единицы) — псевдокод/сигнатуры C#;
2) схема переноса: что уходит из Paint в layout, что остаётся; по каким точкам ломаются
   текущие GridPaint/PinchGridWindow;
3) план golden-image (сцены, механизм, интеграция в самопроверку);
4) перечень ДОСЛОВНЫХ тел методов, которые нужны тебе для байт-точного дифа на этапе 2
   (классы/методы/ориентировочные зоны из r42 — см. указатель ниже);
5) риски и вопросы к владельцу стандартной формулировкой.
Код-диф в ЭТОМ ходе не нужен — приёмка эскиза ассистентом (КП4.1г: этап 2 — код после
принятого эскиза; фрагменты вставит владелец по твоему перечню из п.4).

========================================================================
3. УКАЗАТЕЛЬ ПО ИСХОДНИКАМ (r42 = «код 42» в твоём контексте)
========================================================================
• PinchEngine.cs: class PinchStream / PinchInterval / PinchResult / PinchExchange / PinchUtility /
  PinchDesign + PinchEngine.Target/Design/ScanDTmin/BuildComposites/SynthesizeRegion — модель данных
  для layout (потоки, ветви, обменники, утилиты, предупреждения).
• Класс PinchGridWindow (отдельный файл, ~19 КБ): поля LaneH=34/LaneGap=12/LeftMargin=170/
  RightMargin=140/TopMargin=92/BottomMargin=70; методы ToggleFull, SetZoom, BuildLabels, OnPaint,
  DrawScene, DrawLabels, RenderForReport, SaveImage; Size(1180,720), MinimumSize(760,520).
• PinchStudio.cs (52 КБ): GridPaint (inline рендер сетчатой на панели, «геометрия в Paint»),
  BuildNetTab (кнопки «Синтезировать сеть»/«Оптимизировать»/«Сетчатая в окне…»/«Отчёт по пинчу…»),
  DoDesign/DoOptimize (вызов PinchEngine.Design), ImportFromScene (тянет трубы |ΔT|≥2 как потоки —
  Сп2, но учти происхождение поток↔объект в модели), SavePinchReport (пинч-отчёт DOCX).
• Конвенции: InvariantCulture, тёмная тема (константы PinchStudio; централизация — Сп0-наблюдение),
  правило паритета (TGB будет ссылаться на те же Core-исходники — НЕ ломать сигнатуры ядра).
• Не трогать: PinchEngine-математику, TEMP-DIAG R39-2/R40-1 (снос — после прогона ×2), эталоны
  hydraulic/energy (UI не тестирует их).
