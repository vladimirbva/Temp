# ТЗ на разработку Terminal-Generatora Budcad (TGB)

Статус: v1.1 (02:1x 15.11.2026) · Заказчик: владелец BUDcad · Исполнитель: AI-ассистент
Обновление v1.1: расширения R1–R4 РЕАЛИЗОВАНЫ в BUDcad (v61: R1 составы X1..X40→Y1..Y40;
v62: R2 заданный расход, R3 параметры экземпляра, R4 история/шаблоны) — ТЗ скорректировано:
раздел 7 (семантика Q_<выход>), точки сопряжения 13–15, фазы (раздел 16), пример манифеста.
Первичная редакция: v1.0 (01:4x 15.11.2026).
Назначение: подробное техническое задание на создание отдельной WinForms C#-программы TGB для
генерации методов расчётных терминалов (.bmethod) с визуальным редактором и редактором математики —
в пределах возможностей BUDcad. Позже — по этому ТЗ — работа.
Сопутствующие документы: PSR BUDcad (reports/PSR_BUDcad_v55.txt), реестр п.120
(work/budcad_backlog_registry.txt), полный код BUDcad v60.

---

## 1. Термины и определения

- **BUDcad** — основная программа (WinForms, net8.0-windows), редактор технологических схем.
- **Терминал (расчётный терминал)** — объект сцены BUDcad, Kind = ObjectKind.CalcTerminal;
  «микропроцессор» схемы: чёрный ящик с уравнениями, загружаемый из внешнего файла метода.
- **Метод (.bmethod)** — файл формата v1 (JSON-манифест), единый носитель всего: манифест +
  визуал + математика (уравнения-строки) + требования к входам/выходам (порты) + параметры.
- **TGB (Terminal-Generator Budcad)** — отдельное WinForms-приложение для разработки методов:
  визуальный редактор терминала и редактор математики; результат — файл .bmethod.
- **Общая модель** — файл BUDcad_2.1/BMethodModel.cs (классы манифеста, валидатор BMethodLoader,
  компилятор выражений BMethodExprCompiler). ЕДИНЫЙ ИСТОЧНИК для BUDcad и TGB: включается в оба
  проекта через `<Compile Include>`. Дублирование модели в TGB ЗАПРЕЩЕНО.
- **Величины** — именованные числовые переменные, доступные уравнениям метода (канонический
  список — см. раздел 7).
- **Реверс** — поток через порт терминала в направлении, противоположном оговоренному
  (на входном порту — ИЗ терминала; на выходном — В терминал). Запрещён; фиксируется тревогой.

## 2. Цель и границы

**Цель:** дать владельцу инструмент, которым метод терминала создаётся целиком до BUDcad:
визуал, порты (входы/выходы), параметры и математика — и который затем подгружается в BUDcad
одной кнопкой «Загрузить метод (.bmethod)...» без каких-либо правок со стороны BUDcad.

**В рамке (Ф1):**
1. Создание/открытие/сохранение файла .bmethod формата v1 (раздел 5).
2. Визуальный редактор: форма (box/round), цвет (#RRGGBB), подпись; живой предпросмотр того,
   как терминал будет выглядеть на канве BUDcad (раздел 9).
3. Редактор портов: входы/выходы, тип величины, единицы (раздел 10).
4. Редактор параметров: имена, значения по умолчанию, единицы, границы (раздел 11).
5. Редактор математики: уравнения-строки a = f(b1..bn) с проверкой на лету — тем же валидатором
   и компилятором, что в BUDcad (раздел 8).
6. Валидация метода целиком (правила раздела 6) с сохранением до устранения ошибок.
7. Каталог-совместимость: файлы TGB сохраняются в BUDcad_Methods; подгружаются BUDcad без доработок.

**Вне рамки Ф1 (в последующих фазах — раздел 16):** позиции штюцеров в манифесте (v1.1),
переопределение значений параметров экземпляра, библиотеки методов с версиями/changelog,
шаблоны методов (пиролиз углеводородов, полимеризация этилена и др.), графический конструктор
уравнений (drag-drop узлов), автогенерация формулы по таблице данных.

**Жёсткое правило сопряжения:** TGB не «договаривается» с BUDcad ни о чём сверх того, что BUDcad
уже исполняет. Всё, что TGB генерирует, должно быть принято BUDcad v60+ без единой правки кода
BUDcad. Если ТЗ требует новую возможность BUDcad — она фиксируется как «расширение» (раздел 16)
и реализуется в BUDcad ОТДЕЛЬНО до включения в рамку TGB.

## 3. Контекст сопряжения (что уже умеет BUDcad v60)

- Подгрузка: свойства терминала → «Загрузить метод (.bmethod)...» (OpenFileDialog от каталога
  BUDcad_Methods) → TerminalApply.PickAndLoad → BMethodLoader.TryLoadFile (чтение + hash SHA256
  + валидация) → при браке — MessageBox со списком ошибок и статус «ошибка подгрузки»;
  при успехе — TerminalApply.ApplyTo: в объект интегрируются визуал (TerminalLabel/ColorHex/Shape),
  порты (TerminalPorts), параметры (TerminalParams), выражения (TerminalMethodExprs),
  hash (TerminalMethodHash), статус; затем SyncTerminalNozzlesFromPorts — порты становятся
  штюцерами (по имени, существующие не удаляются).
- Без метода: терминал вне схемы — штюцеров нет, узлов сети нет.
- Расчёт: TerminalEngine.StepTerminals каждый тик после решения сети: фактические расходы
  по портам → величины (параметры + Q_/P_/T_ портов) → последовательное исполнение уравнений
  (кэш компиляции по hash) → выходные P_/T_ применяются к границам out-портов в следующем тике;
  Q_out сохраняется в величинах порта (в сеть не вписывается — нет режима «заданный расход»).
- Реверсы: запрещены; тревога = TerminalReverseAlarm + список портов + знак «!» на канве +
  warning в логе (edge-trigger) + красная строка в окне терминала.
- Сериализация: всё интегрированное содержимое сохраняется в проекте (ObjectData) — BUDcad
  работает независимо от файла метода; hash используется только для сверки версии файла.
- Редактирование метода из BUDcad НЕ предусмотрено (решение владельца) — только TGB + новая подгрузка.

## 4. Архитектура TGB

4.1. Отдельное WinForms-приложение (net8.0-windows, UseWindowsForms=true), отдельный проект
в solution BUDcad_2.1.sln (рекомендуемое имя BUDcadTerminalGenerator) ИЛИ самостоятельное
решение — по решению владельца; вариант «в solution» предпочтителен: общий файл модели подключается
относительным путём без копий.

4.2. Состав (Ф1):
- Program.cs — точка входа (STAThread, EnableVisualStyles).
- MainForm — главное окно: вкладки (см. 4.3), панель статуса валидации, меню/кнопки
  «Новый/Открыть/Сохранить/Проверить».
- MethodModelHost — единственная точка доступа к BMethodModel.cs (Include; править модель
  разрешено ТОЛЬКО в общем файле; правки должны сохранять совместимость обоих потребителей).
- PreviewCanvas — предпросмотр терминала (раздел 9.3).
- ExpressionGrid — редактор математики (раздел 8).
- PortsGrid / ParamsGrid — редакторы портов и параметров.

4.3. Вкладки главного окна (Ф1):
1) «Общее» — имя метода, автор, версия, визуал (форма/цвет/подпись) + предпросмотр.
2) «Порты» — таблица портов (имя/направление/тип/единицы) + подсказки валидации в строке.
3) «Параметры» — таблица параметров (имя/значение/единицы/Min/Max).
4) «Математика» — список уравнений Output = Expression (+комментарий), кнопка «Проверить»,
   панель ошибок валидации, панель «Доступные величины» (генерируется BMethodLoader.BuildVariables
   + InputVariableNames — с пометкой «только чтение»/«назначаемая»).
5) «Проверка» — сводный отчёт: ошибки валидации, результат компиляции (список compiled),
   список величин, hash.

4.4. Принцип «один валидатор»: любые проверки TGB выполняются ТОЛЬКО методами общей модели
(BMethodLoader.Parse/Validate/CompileAll/BuildVariables/InputVariableNames/HashOf). TGB не
переопределяет сообщения об ошибках и не добавляет своих правил — иначе появятся расхождения
между «прошёл TGB» и «принял BUDcad».

## 5. Формат .bmethod v1 (полная спецификация)

Файл: UTF-8 без BOM; JSON; pretty-печать (WriteIndented), допускаются комментарии и висячие
запятые при чтении (ReadCommentHandling.Skip, AllowTrailingCommas=true — как в BUDcad).
Имя файла: <Sanitize(Name)>.bmethod (Sanitize: пробелы → '_', недопустимые символы пути → '_').

Поля (кейс-инсензитив при чтении):

| Поле | Тип | Обяз. | Правило |
|---|---|---|---|
| format | int | да | только 1 |
| name | string | да | непустое, ≤100 символов |
| author | string | нет | свободный текст |
| version | string | да | непустое (рекомендуется «1.0») |
| visual.shape | string | нет | «box» или «round» (пусто → box) |
| visual.colorHex | string | нет | «#RGB» или «#RRGGBB» (пусто → «#1A1C22») |
| visual.label | string | нет | подпись на канве, ≤60 символов (пусто → name) |
| ports[] | array | да | ≥1 порт; ≥1 вход; ≥1 выход |
| ports[].name | string | да | непустое; уникальное; латиница/цифры/«_»; идентификатор |
| ports[].direction | string | да | «in» или «out» |
| ports[].kind | string | да | «Q», «T» или «P» (тип основной величины связи) |
| ports[].units | string | да | непустое (например «м³/ч», «бар», «°C») |
| params[] | array | нет | |
| params[].name | string | да | непустое; уникальное; не совпадает с именами портов; идентификатор |
| params[].value | double | да | значение по умолчанию (InvariantCulture) |
| params[].units | string | нет | |
| params[].min / .max | double? | нет | если заданы оба: min ≤ max |
| exprs[] | array | нет | |
| exprs[].output | string | да | непустое; уникальное; назначаемая величина (см. раздел 7) |
| exprs[].expression | string | да | непустое; валидное по грамматике раздела 8.3 |
| exprs[].comment | string | нет | |

Пример (минимальный валидный метод):
```json
{
  "format": 1,
  "name": "Демо-метод",
  "author": "",
  "version": "1.0",
  "visual": { "shape": "box", "colorHex": "#1A1C22", "label": "Демо" },
  "ports": [
    { "name": "in_feed",  "direction": "in",  "kind": "Q", "units": "м³/ч" },
    { "name": "out_dist", "direction": "out", "kind": "Q", "units": "м³/ч" }
  ],
  "params": [ { "name": "K", "value": 1.8, "units": "−" } ],
  "exprs": [ { "output": "P_out_dist", "expression": "K", "comment": "выходное давление, бар" } ],
  "history": [
    { "version": "1.0", "date": "2026-11-15", "note": "первая версия" }
  ]
}
```

Обязательное правило полноты: КАЖДЫЙ выходной порт должен быть «обслужен» хотя бы одним
выражением — т.е. в exprs существует output = имя порта (алиас расхода) или Q_<имя> / P_<имя> /
T_<имя> этого порта. Иначе метод не валиден.

## 6. Валидация (полный перечень правил — БЕЗ ИЗМЕНЕНИЙ повторяет BMethodLoader.Validate)

ТGB выводит те же сообщения, что BUDcad. Перечень (кратко):
1) JSON не разобран → «JSON не разобран: <причина>».
2) format != 1 → «format: поддерживается только 1 (факт N)».
3) name: пустое или >100 символов.
4) version: пустое.
5) visual.shape вне {box, round}; visual.colorHex не #RGB/#RRGGBB; visual.label >60.
6) ports: пусто; пустое имя; дубликат имени; direction вне {in,out}; kind вне {Q,T,P}; пустые units.
6а) history[] (v62, R4): если поле присутствует — каждый элемент: непустая Version (иначе
    «history[i]: пустая версия записи»); Date/Note — свободные. Пустой history[] — не ошибка.
7) params: пустое имя; дубликат; совпадение с именем порта; min > max.
8) exprs: пустой Output; дубликат Output; Output — входной порт; Output — параметр;
   Output — входная величина порта (Q_/P_/T_ входа или имя входного порта) — только чтение;
   пустое выражение.
9) Неизвестная функция — только exp, ln, sqrt, pow, min, max, abs, sin, cos, tan.
10) Неизвестная величина в выражении (не в каноническом списке раздела 7 и не промежуточная).
11) Самоприсваивание/цикл: Output не может использоваться в собственном выражении и в
   выражениях ДО его назначения (порядок выражений — последовательный, раздел 8.2).
12) Выходной порт не обслужен (см. правило полноты раздела 5).
13) Нет входов или нет выходов среди портов.
14) CompileAll: демо-прогон на единицах — NaN/Inf → «демо-вычисление дало не число».

## 7. Канонические величины (контракт с BUDcad — строго)

Канонический список величин метода = BuildVariables(m):
1) Параметры: <имя параметра> — в порядке манифеста.
2) По каждому порту (в порядке манифеста), четыре слота:
   - <имя порта> — АЛИАС расхода порта (равен Q_<имя>); заполняется тем же значением;
   - Q_<имя> — фактический расход по связи порта, м³/ч, СО ЗНАКОМ: на входном порте
     положительный = поток В терминал (норма), отрицательный = реверс; на выходном порте
     положительный = поток ИЗ терминала (норма), отрицательный = реверс;
   - P_<имя> — давление, бар: на входном порте — P объекта терминала (граница источника);
     на выходном порте — вычисленное методом значение предыдущего тика (если выражение
     назначило P_<имя>), иначе P объекта;
   - T_<имя> — температура, °C: аналогично P_<имя>.
3) Промежуточные: Output'ы выражений по порядку (новые имена).

**Только чтение (назначение запрещено):** параметры; для входных портов — <имя>, Q_<имя>,
P_<имя>, T_<имя>.
**Назначаемые:** для выходных портов — <имя> (алиас расхода), Q_<имя>, P_<имя>, T_<имя>;
любые новые имена (промежуточные).

Семантика применения в BUDcad (для справки TGB, менять запрещено):
- P_<выход> и T_<выход> — если назначены выражениями, применяются к границе out-порта в
  следующем тике (RefreshDynamicBoundaryConditions/BuildNetwork);
- Q_<выход> — вычисленный расход ВПИСЫВАЕТСЯ в сеть (v62, R2): управление давлением границы
  out-порта по ошибке расхода (секантная подстройка по локальной чувствительности Q(P),
  шаг ≤0.3 бар/тик, сходится за несколько тиков). Если назначены одновременно P_<выход> и
  Q_<выход> — приоритет у Q (P управляется регулятором). Q_target ≤ 0 игнорируется регулятором
  (реверс-тревога остаётся — и это правильно: строго заданные направления);
- состав потока: X1..X40 — входной состав (read-only), Y1..Y40 — выходной (назначаемые,
  дефолт Yi=Xi, нормировка суммы, кламп отрицательных) — применяется ко ВСЕМ out-портам
  (v61, R1); если ни один Yn не назначен — состав объекта терминала;
- параметры экземпляра: значения из TerminalParamOverrides имеют приоритет над значениями
  метода (v62, R3) — переопределяются в свойствах терминала BUDcad, hash метода не меняется.

## 8. Редактор математики

8.1. Модель: список выражений (Output, Expression, Comment) в ПОРЯДКЕ вычисления — порядок
строк в таблице = порядок исполнения в тике. Переупорядочивание — законно (drag/кнопки ↑↓);
валидация пересчитывается после каждой правки.

8.2. Последовательность: выражение k может ссылаться на: параметры, величины портов, промежуточные
Output'ы выражений 1..k−1 и свой... НЕТ — самоприсваивание запрещено (Output не может входить в
собственное выражение). Циклы по построению невозможны.

8.3. Грамматика выражений (в точности BMethodExprCompiler):
- числа (InvariantCulture, включая 1e-3), идентификаторы [A-Za-z_][A-Za-z0-9_]*;
- операторы: + − * / ^ (степень), унарный −, скобки;
- приоритет: ^ > * / > + −; правоассоциативное ^;
- функции одного аргумента: exp, ln, sqrt, abs, sin, cos, tan; двух: pow(x,y), min(x,y), max(x,y);
- разделитель аргументов — запятая; пробелы допустимы; иные символы — ошибка валидации.
- ЛОКАЛИ: во время разработки показывать числа по локали, в файл и в компилятор — только
  InvariantCulture (точка). TGB обязан конвертировать (иначе расхождения Windows-локали).

8.4. Проверка на лету: после правки любой ячейки/порядка — BMethodLoader.Parse → Validate →
CompileAll по текущему черновику; панель ошибок обновляется; выражение с ошибкой подсвечивается
(сообщение — как в BUDcad, без переформулировок).

8.5. Ограничение объёма: до 100 выражений в методе (обоснование владельца: «до 100 строковых
корреляций»). Превышение — предупреждение валидации.

8.6. В окне математики показывается сгенерированный список доступных величин с разделением
«только чтение» / «назначаемые» (BuildVariables + InputVariableNames) — чтобы разработчик
метода не угадывал имена.

## 9. Визуальный редактор

9.1. Параметры визуала — ровно те, что BUDcad исполняет: shape (box/round), colorHex (#RGB/#RRGGBB),
label (≤60). Больше — не предлагать в Ф1.

9.2. Цвет: поле + палитра (стандартный ColorDialog) + проверка формата; в файл — строка вида
«#RRGGBB».

9.3. Предпросмотр: мини-канва, повторяющая DrawCalcTerminal BUDcad: прямоугольник/эллипс с
заливкой выбранным цветом, контур, подпись (label или name), плашка «метод не загружен» не
показывается (в TGB метод всегда в работе). Цель предпросмотра — доверие: что видно в TGB,
то увидится в BUDcad. Пропорции предпросмотра — фиксированные, не зависят от сцены.

9.4. Порты на предпросмотре (Ф1): показываются списком сбоку (in — слева, out — справа) БЕЗ
позиционирования на фигуре; позиции штюцеров в BUDcad назначаются автоматически (чередование
AngleDeg 0/180). Точное позиционирование — Ф2 (расширение формата v1.1: port.angleDeg/heightFrac
+ правка SyncTerminalNozzlesFromPorts в BUDcad).

## 10. Редактор портов

Таблица: имя (валидация идентификатора на месте), направление (ComboBox in/out), тип величины
(Q/T/P), единицы (свободный текст, непустое). Контролируемые дубликаты — сразу подсветка.
Правило сопряжения: имя порта ДОЛЖНО совпадать с тем, что увидит пользователь в BUDcad как
штюцер (SyncTerminalNozzlesFromPorts создаёт штюцеры с именами портов) — переименование порта
в методе после загрузки в проект = «новая версия метода» и повторная подгрузка (hash сменится,
TGB обязан предупреждать: имя порта участвует в fingerprint).

## 11. Редактор параметров

Таблица: имя, значение (InvariantCulture), единицы, Min, Max (обязательность — нет; оба — правило
min≤max). Значения параметров «входят в BUDcad уже заложенными» (решение владельца): в BUDcad они
не редактируются (Ф1); переопределение значений экземпляра — расширение (раздел 16, Ф2).

## 13. Требования к сохранению

- Сохранение запрещено при валидации с ошибками (кнопка «Сохранить» сначала выполняет проверку).
- После сохранения — отчёт: путь, hash (SHA256), список портов/параметров/выражений.
- Повторное сохранение того же метода — допустимо (тот же путь; hash может измениться — это
  легальная «новая версия», BUDcad зафиксирует смену hash при подгрузке).

## 14. Нефункциональные требования

1) Целевой фреймворк: net8.0-windows (как BUDcad); без внешних пакетов сверх WinForms.
2) Сборка: 0 ошибок, 0 предупреждений кода (стандарт проекта).
3) Темы/шрифт: тёмная палитра BUDcad (фон #1E222A/#181B21, текст #FFFFFF, вторичный #96A0AF) —
   согласованность с линейкой программ владельца.
4) Не хранить состояние между сессиями сверх файла метода (без реестра/конфигов в Ф1).
5) Диагностика: все ошибки — человекочитаемые, с указанием строки/поля; без стектрейсов в UI.
6) Локаль: все вычисления и сериализация — InvariantCulture.

## 15. Тестирование и приёмка

Критерии приёмки Ф1:
1) Метод, созданный в TGB, загружается в BUDcad v60+ без ошибок; штюцеры и визуал появляются.
2) Метод с умышленной ошибкой (любая из раздела 6) — отклонён BUDcad с тем же сообщением,
   что показал TGB (расхождение сообщений — дефект).
3) Изменённый метод (другой hash) — подгружается повторно, BUDcad фиксирует смену hash.
4) Реверс-сценарий: метод с назначенным P_<выход> < P источника → тревога реверса в BUDcad —
   поведенческая проверка сопряжения.
5) Собственный прогон тестов модели (ColumnEngine/Terminal/BMethod — 183+) остаётся зелёным.
6) Сборка TGB — 0 предупреждений кода.

## 16. Фазы и расширения (решения владельца)

- **Ф1 (рамка настоящего ТЗ)** — всё выше, формат v1, без правок BUDcad.
- **РЕАЛИЗОВАНО В BUDcad (доступно TGB уже сейчас):**
  a) (v61) составные величины X1..X40 → Y1..Y40 — валидатор/компилятор/движок поддерживают;
     TGB включает их в список доступных величин (BuildVariables — автоматически);
  b) (v62) заданный расход: назначенный Q_<выход> вписывается в сеть через управление P
     (секантная подстройка); предупреждение о совместном назначении P_+Q_;
  c) (v62) переопределение параметров экземпляра — в свойствах терминала BUDcad;
     TGB показывает значения метода как дефолты;
  d) (v62) история метода: опциональное поле history в манифесте + заметка о смене версии
     при подгрузке; шаблоны методов в утилите-предшественнике (демо/пиролиз/полимеризация).
- **Ф2 (остаток, требует согласованных правок BUDcad):**
  a) v1.1 манифеста: позиции штюцеров (port.angleDeg/heightFrac) — правка
     SyncTerminalNozzlesFromPorts; предпросмотр позиций в TGB;
  b) импорт из XLSX (таблица корреляций) с проверкой валидатором;
  c) экспорт метода в человекочитаемый PDF.
- **Ф3** — библиотека методов: версии/авторы/каталог с поиском, changelog-редактор (history
  уже реализован в BUDcad — TGB встраивает его в свой UI).
- **Ф4 (идея, вне текущих планов)** — графический конструктор уравнений (узлы-операторы) и
  автогенерация формулы по таблице данных (регрессия с ограничениями валидатора).
