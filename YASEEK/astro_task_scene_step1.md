## О ПРОЕКТЕ (читай обязательно)

**Yaseek** — PWA-трекер кормления младенца. Один пользователь-семья (мама/папа, до 2 взрослых
+ до 2 детей). Стек: ASP.NET Core (.NET 10), SQLite (EF Core), клиент — vanilla JS без сборщиков
и фреймворков (один файл wwwroot/app.js ~380 КБ, модалки через `<dialog>`, тосты, офлайн-очередь
в localStorage), Service Worker (wwwroot/sw.js), графики — Chart.js (уже в проекте).

### Структура проекта
- `src/Yaseek.Api/Program.cs` — точка входа, версии (`AppBuild.Current`).
- `src/Yaseek.Api/Program.Ep.*.cs` — эндпоинты по зонам (Feeds, Stock, Chat, Journal, Push, Admin, Doctor, Reports, Export).
- `src/Yaseek.Api/AppDb.cs` — EF Core DbContext + миграции (SchemaVersion 1..12).
- `src/Yaseek.Api/wwwroot/app.js` — весь клиент (~380 КБ). `index.html` (вкладки, 23 `<dialog>`),
  `styles.css`, `sw.js` (CACHE 'yaseek-v130', пре-кэш-список файлов).
- Существующие вкладки клиента (index.html): Кормления, Склад, Журнал, Статистика, Чат, Настройки.
- Данные sync: /api/sync отдаёт всё состояние (кормления, склад, журнал, чат, hunger-прогноз P(t)…)

### Правила проекта (несоблюдение = задача отклоняется)
1. **Клиент — vanilla JS, без сборщиков/React/Vue.** Серверные зависимости НЕ добавлять (кроме
   одного исключения ниже: файл Three.js кладётся локально в wwwroot — это статический файл,
   не NuGet).
2. **Офлайн обязателен:** Three.js и модели — только локальные файлы в wwwroot, попадающие в
   PWA-кэш. CDN в рантайме запрещён.
3. **Секьюрити/входы/авторизация — ЗАМОРОЖЕНЫ.** Не трогать: логин/токены (X-Family-Token),
   RLS, дедуп ClientId.
4. Версионирование: AppBuild.Current = "15.15"; sw.js CACHE = 'yaseek-v131'; index.html ?v=15.15
   (и sw-пре-кэш: three.module.js + все модели — НЕ пре-кэшить модели сразу (600 КБ) — пре-кэшить
   только three.module.js, модели кэшировать «cache-first» по факту первого запроса).
5. Таблица MetabolismWeights — не трогать. Миграций НЕТ в этом шаге.
6. Сцена — ОТДЕЛЬНАЯ вкладка «Комната», НЕ замена главного экрана. Существующие вкладки и
   экраны не меняются (кроме добавления одной кнопки-вкладки).
7. Производительность: рендер-цикл ставится на паузу при visibilitychange (document.hidden);
   cap 30 FPS; pixelRatio ≤ 2.

## ШАГ 1: каркас вкладки «Комната»

### Цель
Открыть вкладку «Комната» и увидеть статичную 3D-комнату со всеми объектами и работающими
переходами по клику. Ребёнок — базовая статичная фигура с микроанимацией дыхания (без сложных
анимаций, сигналов и смены стадий — это ШАГ 2).

### Требования

**R1. Вкладка.**
- В index.html новая вкладка «Комната» (иконка — дом/кровать; стили как у остальных вкладок).
- Контейнер: <canvas> на весь доступный размер, ресайз по ResizeObserver.
- Lazy import Three.js при первом открытии (до этого — заглушка «загрузка комнаты…»).
- Если WebGL недоступен — показать текст «3D не поддерживается этим браузером», вкладка не падает.

**R2. Комната.**
- Пол 6×6 м: floorFull масштабом на весь пол (или сеткой 2×2 — как в README_ASSETS).
- Стены: задняя (север) — wallWindow (окно в центре), боковые — wall, углы — wallCorner.
  Передняя стена НЕ ставится (камера смотрит с «вырезанной» стороны — классический dollhouse-вид).
- Дверь doorway на восточной стене.
- Освещение: AmbientLight + DirectionalLight. В ШАГЕ 1 — дневной фикс (свет окна — ШАГ 3).

**R3. Раскладка объектов (по карте README_ASSETS).**
- Центр: кроватка bedSingle + pillow (ребёнок лежит в ней — см. R5).
- Зона кухни (северо-восток): kitchenCabinet + kitchenCabinetDrawer + kitchenFridgeSmall +
  kitchenSink + kitchenStove + kitchenCoffeeMachine — клик → вкладка «Кормления».
- Шкаф-склад (северо-запад): bookcaseOpenLow (+ bookcaseClosed рядом как второй шкаф) —
  клик → вкладка «Склад».
- Уголок ИИ-доктора (юго-восток): laptop на sideTableDrawers + pottedPlant — клик →
  существующий блок «AI-доктор» (программно открыть существующую вкладку «Журнал» и скролл
  к блоку доктора ИЛИ открыть соответствующий `<dialog>` — как удобнее, но ПЕРЕХОД должен
  вести к существующей функции, дублирования UI НЕ создавать).
- Стол статистики (юго-запад): table + chairDesk — клик → вкладка «Статистика».
- Горшок/унитаз (зона санузла у восточной стены): toilet — клик → существующий диалог
  «Отметить стул» (существующий `<dialog>` дефекаций).
- Тумбочка настроек: sideTableDrawers у южной стены — клик → вкладка «Настройки».
- Столик с телефоном (чат): sideTable + телефон из примитива (маленький бокс 0.07×0.14×0.01
  тёмный) — клик → вкладка «Чат».
- Уют: rugRound у кроватки, rugRectangle у кухни, plantSmall1/plantSmall2 по углам, bear рядом
  с кроваткой, radio на кухонном шкафу, lampRoundFloor у кроватки, lampSquareCeiling на потолке.
- Имя ребёнка кубиками на полу (блок-буквы из боксов — «ЯН» — имя берётся из sync) — деталь
  «изюминки», обязательна.

**R4. Хотспоты и переходы.**
- Указатель курсора pointer при наведении на кликабельный объект (raycaster).
- Клик: анимация камеры (лерп позиции+target к объекту, 300–500 мс, easeInOut) → после
  завершения — переход на целевую вкладку (тот же программный вызов, что и при клике по вкладке).
- Возврат на вкладку «Комната» — камера возвращается в исходную точку (обратный лерп).

**R5. Ребёнок (база, ШАГ 2 углубит).**
- Фигура малыша из примитивов (сфера-голова, цилиндр-тело, ручки/ножки капсулами) — лежит
  в кроватке. Размер тела пропорционален возрасту (возраст из sync: дни).
- Микроанимация дыхания: масштаб грудной клетки ±1.5% с периодом ~2.5 с. Других анимаций нет.
- Заголовок сцены: тост «Комната <имя>» при первом открытии (существующий toast-механизм).

**R6. Сигналы — заглушки (реализация в ШАГЕ 2).**
- Каркас: объекты помечаются атрибутом hotSpot={action: 'feeds'|'stock'|'poop'|'doctor'|
  'stats'|'chat'|'settings'}. В ШАГЕ 1 клики работают всегда; подсветка-сигналы (голод, «!»,
  дрожь телефона) — НЕ реализовывать (данные уже есть в sync — ШАГ 2 их возьмёт).

### Приёмка (проверь сам перед сдачей)
1. Полный тест-пакет зелёный (192 — сервер не менялся, кроме версий; смоук обязателен).
2. Смоук: /health ok, /api/version 15.15; вкладка «Комната» открывается, все объекты на местах,
  клики ведут на правильные вкладки/диалоги; окно остаётся без света-смены (день, ШАГ 1).
3. Скрытие сцены (переход на другую вкладку) — рендер-цикл останавливается (не тратит батарею);
  возврат — возобновляется.
4. Офлайн: после первого открытия сцены повторное открытие без сети работает (кэш PWA).
5. Версии: sw v131, ?v=15.15, AppBuild.Current 15.15; дамп кода полным файлом.

### Что НЕ делать
- Не менять существующие вкладки/логику (кроме добавления одной вкладки).
- Не трогать сервер, кроме версии AppBuild и (если надо) Mime-типа .glb — статические файлы
  уже раздаются статикой ASP.NET; проверь Content-Type для .glb (model/gltf-binary) —
  при необходимости добавь маппинг в Program.cs (1 строка).
- Не реализовывать сигналы и свет-смену (ШАГИ 2–3).
