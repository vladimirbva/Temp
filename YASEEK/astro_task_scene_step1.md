# ЗАДАЧА: Сцена «Комната» — шаг 1 (каркас) → v15.15

## О ПРОЕКТЕ (читать обязательно)
Yaseek — трекер кормления грудного ребёнка (родился 15.10.2026). Стек: C# / ASP.NET
(Kestrel, SQLite, миграции) + vanilla JS-клиент (app.js, PWA со service worker).
Структура файлов — в разделе «Структура» ниже. Родители фиксируют кормления и сон,
приложение прогнозирует момент голода (движок P(t): μ, σ, Circ — формулы НЕ трогать,
см. «Не делать»), присылает push-уведомления. Версии: AppBuild.Current в Program.cs,
sw.js CACHE='yaseek-vNNN', index.html ?v=NNN — все три меняем синхронно.
Текущая база: v15.14 / sw yaseek-v130 / ?v=15.14 (192 теста зелёные).

## ЦЕЛЬ ШАГА 1
Добавить вкладку «Комната» — 3D-сцену «детская комната» на Three.js: статичные объекты
(раскладка ниже), ребёнок-малыш из примитивов, переходы по клику на объекты в существующие
вкладки/диалоги. Вкладка ДОБАВЛЯЕТСЯ к существующим (не заменяет главный экран).
Сигналы и продвинутый ребёнок — в шаге 2 (не этот шаг).

## Требования
### R1 — Three.js локально
- three.module.min.js r160+ (версия — твоя, не ниже r160) положи в
  `src/Yaseek.Api/wwwroot/lib/three/three.module.min.js`. Это текстовый JS-файл — он попадёт
  в дамп кода как обычная секция.
- GLTFLoader.js из three/examples/jsm/loaders/ — РАЗРЕШЁН вторым локальным файлом в
  `src/Yaseek.Api/wwwroot/lib/three/GLTFLoader.js` (это не CDN и не NuGet — статический файл
  в wwwroot). Подключение: import map («three» → ./lib/three/three.module.min.js,
  «three/addons/» → ./lib/three/) либо правкой относительного импорта — на твой выбор;
  офлайн обязателен.
- В app.js — динамический import() ТОЛЬКО при первом открытии вкладки «Комната» (лениво),
  кэшируй модуль в переменной. До открытия вкладки Three.js не грузится.
- НИКАКОГО CDN в рантайме.

### R2 — Ассеты
Модели Kenney Furniture Kit (CC0) лежат в `yaseek-room-assets-kenney-furniture-cc0.zip`:
распакуй 1:1 в `src/Yaseek.Api/wwwroot/assets/room/` (31 GLB + LICENSE-CC0.txt +
README_ASSETS.md). README_ASSETS.md внутри — карта «объект сцены → модель», следуй ей.
GLB — бинарные файлы: в текстовый дамп кода НЕ вносить (в full_code упомяни список путей
одной строкой на файл без содержимого). Если Amvera/сервер отдаёт .glb с неверным
Content-Type — добавь строку маппинга в Program.cs (model/gltf-binary).

### R3 — Сцена (каркас)
- Пол, стены, окно — из примитивов (BoxGeometry) или моделей floorFull/wall/wallCorner/
  wallWindow/doorway. Раскладка комнаты — на твой вкус, но зона кормления (кухня), кроватка,
  шкаф-склад, toilet, столик чата, стол статистики, уголок ИИ-доктора, тумбочка настроений
  (настройки) — читаемо различимы. Камера — ортографическая или перспектива с фикс. позицией.
- Статические объекты из ассетов: кроватка (bedSingle + pillow), кухня (kitchenCabinet,
  kitchenFridgeSmall, kitchenSink, kitchenStove, kitchenCoffeeMachine), склад
  (bookcaseOpenLow + bookcaseClosed), toilet, стол статистики (table + chairDesk),
  тумбочка настроений (sideTableDrawers), свет (lampRoundFloor + lampSquareCeiling),
  уют (plantSmall1/2, pottedPlant, bear), ноутбук ИИ-доктора (laptop).
- Ребёнок: простой мультяшный малыш из примитивов (капсула/сферы), лежит в кроватке.
  Микроанимация дыхания (масштаб ±1.5%, период ~2.5 с) — можно уже в шаге 1.
- Имя ребёнка «кубиками» на полу (примитивы-буквы или Canvas-текстура — твой выбор;
  в шаге 1 можно константой «Ян», в шаге 2 — из данных).
- БЕЗ звука в шаге 1.

### R4 — Хотспоты и переходы
Клик по объекту → лёгкий «наезд камеры» (лерп позиции/зума 300–500 мс) → переход в
соответствующую вкладку через существующий switchTab() или открытие существующего диалога:
кухня → вкладка «Кормление» (кормление); шкаф → «Склад»; toilet → диалог дефекации
(если ведётся); столик с телефоном → «Чат»; стол со статистикой → «Статистика»;
уголок с ноутбуком → ИИ-доктор; тумбочка с ключами → «Настройки». Возврат из вкладки в
комнату — мягкая приёмка (камера отъезжает в исходную позицию). Сигнальные состояния
(«!», бутылочка, дрожание) в шаге 1 — только заглушки-атрибуты hotSpot={action:...},
реализация — шаг 2.

### R5 — Производительность и офлайн
- Рендер-цикл: пауза при document.visibilitychange (вкладка скрыта — не рендерим).
- Cap 30 FPS, pixelRatio ≤ 2 (clamp), resize по контейнеру.
- sw.js: three.module.min.js и GLTFLoader.js — в пре-кэш новой версии CACHE (yaseek-v131);
  модели GLB — НЕ в пре-кэш, кэшировать «cache-first» по факту первого запроса.
- Офлайн: вкладка открывается без сети после первого посещения.
- Старые вкладки не трогать. При ошибке загрузки Three.js — вкладка показывает вежливое
  сообщение «3D недоступно» и не ломает остальное приложение.
