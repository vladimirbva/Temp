## О ПРОЕКТЕ (читай обязательно)

**Yaseek** — PWA-трекер кормления младенца. Один пользователь-семья (мама/папа, до 2 взрослых
+ до 2 детей). Стек: ASP.NET Core (.NET 10), SQLite (EF Core), клиент — vanilla JS без сборщиков
и фреймворков (один файл wwwroot/app.js ~380 КБ, модалки через `<dialog>`, тосты, офлайн-очередь
в localStorage), Service Worker (wwwroot/sw.js), графики — Chart.js (уже в проекте).

### Структура проекта
- `src/Yaseek.Api/Program.cs` — точка входа, версии (`AppBuild.Current`), подключение эндпоинтов.
- `src/Yaseek.Api/Program.Ep.*.cs` — эндпоинты по зонам (Feeds, Stock, Chat, Journal, Push, Admin, Doctor, Reports, Export).
- `src/Yaseek.Api/AppDb.cs` — EF Core DbContext + records DTO + миграции (SchemaVersion 1..12).
- `src/Yaseek.Api/HungerModel.cs` — модель голода (прогнозы кормлений; НЕ трогать в этой задаче).
- `src/Yaseek.Api/wwwroot/app.js` — весь клиент. `index.html` (23 `<dialog>`), `styles.css`, `sw.js` (CACHE 'yaseek-v130').

### Данные, которые уже ведутся (реюзни их)
- Кормления (Feeds): время, объём/ложки, тип (смесь/прикорм), вода.
- Стул (Defecations): время, тип (1=жидкий..5=твёрдый), примечание.
- Сон (Sleeps): start/end UTC, Kind (day/night/active).
- Замеры (Measures): dateUtc, вес (г), рост (см), окружность головы (см) — исторические данные есть.
- Болезни (Illnesses): дата, название, примечание.
- Прививки (Vaccinations): key (из календаря прививок), дата.
- Лекарства (TempMeds): время, доза, название.
- Склад (Stock): смеси/прикорм, запасы, движения.

### Правила проекта (несоблюдение = задача отклоняется)
1. **НЕТ новых серверных NuGet-зависимостей.** Клиент — vanilla JS без сборщиков. Chart.js уже есть.
2. **Секьюрити/входы/авторизация — ЗАМОРОЖЕНЫ.** Не трогать: логин/токены (X-Family-Token), RLS, дедуп ClientId, UNIQUE-миграции.
3. Таблица MetabolismWeights — не трогать, не дропать.
4. Версионирование: AppBuild.Current = "15.15"; sw.js CACHE = 'yaseek-v131'; index.html ?v=15.15.
5. Все новые эндпоинты — под Me(ctx)/Perm(...).
6. **Медицинские тексты — консервативные.** Никаких диагнозов, никаких советов по лечению/дозам.
   Только факты из журнала и формулировки вида «покажите врачу, если…». Любое медицинское
   утверждение — либо факт из данных, либо общепринятая безопасная формулировка.
7. PDF: НЕ делать серверную генерацию PDF. Только печатная страница в клиенте
   (отдельный HTML-блок + window.print(), стили @media print).

## ШАГ: «Сводка для педиатра» (v15.15)

### Цель
Одна кнопка в приложении: «Сводка для врача» — открывается печатная страница, которую можно
показать педиатру на приёме или распечатать.

### Требования

**R1. Данные сводки (сервер).**
- Новый эндпоинт GET /api/doctor-summary/{kidId}?tz=<offset> (v14.9: /api/doctor/{kidId}?tz
  уже существует и возвращает базовую сводку — РЕАЛИЗУЙ НОВЫЙ НЕЗВИСИМЫЙ эндпоинт, старый не трогай):
  возвращает агрегаты за ВСЁ время ребёнка:
  - профиль: имя, дата рождения, возраст в днях/неделях;
  - замеры: все (дата, вес, рост, ОГ), дельты от предыдущего;
  - кормления: среднее количество за сутки (последние 7 и 30 дней), средний интервал (из
    HungerState), суммарный объём за сутки;
  - стул: частота за последние 7/30 дней, распределение типов;
  - болезни: список (дата, название);
  - прививки: список (дата, key);
  - лекарства: список (время, название, доза);
  - сон: средняя длительность ночного сна (последние 14 дней).
- Всё под Perm(me, "view") — только члены семьи.

**R2. Печатная страница (клиент).**
- Кнопка «Сводка для врача» на вкладке «Статистика» (или отдельная вкладка — на твой выбор,
  но не заменяй существующие).
- Открывает полноэкранный блок (не модалку) с вёрсткой под печать: заголовок «Сводка для
  педиатра — <имя ребёнка>, <дата>», секции с таблицами (см. R1), внизу — автоподпись
  «сформировано Yaseek v15.15, <дата-время>».
- Кнопки: «Печать» (window.print()) и «Закрыть». Стили: @media print — скрыть шапку/футер
  приложения, только сводка; шрифт ≥12pt, таблицы с границами, ч/б-совместимость.

**R3. Красные флаги (консервативно).**
- Блок «На что обратить внимание» — ТОЛЬКО безопасные формулировки на основе данных:
  - если нет ни одного замера за 60 дней: «замеры веса/роста не велись более 2 месяцев —
    покажите данные врачу, если есть вопросы о прибавках»;
  - если ≥3 дефекаций типа 1 (жидкий) за 24 ч: «частый жидкий стул — при сохранении обратитесь
    к педиатру»;
  - если 0 дефекаций за 48+ ч при активном ведении стула: «длительное отсутствие стула —
    при повторении обратитесь к педиатру»;
  - если температура в записях лекарств указана ≥38.0 повторно: «повторная температура —
    при сохранении обратитесь к педиатру»;
  - иначе — «заметных сигналов в журнале нет».
- Блок скрывается, если стул/болезни вообще не ведутся (не пугать пользователя).

### Приёмка (проверь сам перед сдачей)
1. Полный тест-пакет зелёный (192 + новые юнит-тесты на агрегаты R1 и флаги R3).
2. Смоук: /api/version 15.15; GET /api/doctor-summary/1?tz=300 на пустой базе — 200, все секции
   нулевые/пустые без ошибок; печатная страница открывается и содержит все секции.
3. window.print() — только клиентский вызов (никаких серверных PDF-библиотек).
4. Старый /api/doctor/{kidId} продолжает работать без изменений.

### Что НЕ делать
- Не менять модель голода, миграций НЕТ (агрегаты считаются на лету).
- Не трогать секьюрити, MetabolismWeights.
- Не добавлять NuGet-пакеты.
- НЕ предлагать отправку сводки на сервер/врач — только печать/показ (врачебные данные остаются
  на устройстве семьи).
